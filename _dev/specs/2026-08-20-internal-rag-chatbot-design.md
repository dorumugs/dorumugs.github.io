## 1. 검증 대상 (사용자 원안)

| 요소 | 위치 | 역할 |
|---|---|---|
| Hermes Agent + Codex OAuth | 집 미니서버 (Docker) | 내부 문서로부터 Q&A 무한 생성 |
| Redis | AWS | **1차 답변자** — 사전생성 Q&A 조회, hit 이면 즉답 |
| Elasticsearch | AWS | miss 시 원문 청크 검색 |
| EC2 GPU | AWS | miss 시 답변 생성 (RAG) |

확정된 전제(사용자 응답):

- 환경: **집 미니서버 + AWS 하이브리드**
- Redis 위치: **1차 답변자**. 사전생성 Q&A 가 본대, RAG 는 fallback
- 서빙 모델: 목표에 `ec2(gpu)` 가 명시되어 있으므로 **EC2 GPU 를 본선**, Bedrock 은 비용 대안으로 병기

## 2. 검증 결과

### 원안 그대로: 6 / 10 — 조건부 부적합

부품 선택(ES 하이브리드 검색, Redis 캐시, GPU 추론, LLM 기반 Q&A 합성)은 전부 표준 패턴이다.
문제는 세 가지가 **결합**할 때 발생한다.

#### 치명적 결함

| # | 결함 | 왜 문제인가 | 처방 |
|---|---|---|---|
| ① | "무한 생성" | 생성 Q&A 총 정보량 ≤ 원문 정보량. 소재가 마르면 모델이 문서에 없는 질문·답을 지어낸다. 무한 생성 = 무한 오염 | "무한"이 아니라 **포화까지**. near-dup 비율 임계로 정지. 진행률은 개수가 아니라 **청크 커버리지** |
| ② | Redis 1차 답변자 | hit 이면 ES·LLM 을 안 탄다 → 잘못된 사전생성 Q&A 가 50ms 만에 영구 반복. exact match 는 hit rate ≈ 0, semantic match 는 임계값이 곧 오답률 | **3단 게이트**. `≥0.95` 즉답 / `0.80~0.95` 는 RAG 로 보내되 해당 Q&A 를 컨텍스트 주입 / `<0.80` 순수 RAG |
| ③ | 검증 루프 부재 | 생성만 있고 채점이 없다. 신뢰도는 프롬프트로 부탁해 얻는 속성이 아니라 게이트로 걸러 얻는 속성 | 2단 게이트. 생성 → **groundedness 자기검증** → 통과분만 적재 |

#### 구조적 결함

| # | 결함 | 처방 |
|---|---|---|
| ④ | 벡터 인덱스 이중화 (Redis Stack vector + ES dense_vector) | 유사질문 매칭은 ES 에 몰고, Redis 는 정규화 질문 해시 → 답변 O(1) exact 캐시만 |
| ⑤ | 생성 모델(Codex) ≠ 서빙 모델(EC2 GPU 오픈모델) → hit/miss 간 품질 단차 | 사전생성 Q&A 를 서빙 모델의 few-shot·증류 데이터로 재사용, 답변 스타일 규격 강제 |
| ⑥ | Redis 가 "본대"인데 인메모리 → 재시작·eviction 으로 소실 | Redis 는 항상 **파생물**. source of truth 는 S3/디스크 JSONL + ES. 언제든 재구축 가능해야 |
| ⑦ | 집 ↔ AWS 경계 | Redis 인터넷 직접 노출 금지. 생성물 JSONL → S3 → AWS 로더가 적재하는 단방향 |
| ⑧ | **임베딩 모델 미결정** — 원안에 없음. 임베딩이 ①신규율 near-dup, ②Redis 3단 게이트, ③ES dense 검색 **세 곳에 동시 사용** → 약하면 셋이 한꺼번에 붕괴. 3절 $\tau$, 4절 0.95/0.80 이 전부 모델 종속 상수 | **로컬 임베딩 + 리랭커(선택지 C)**. 1차 회수는 로컬 임베딩+BM25 로 top-50 넉넉히, 2차는 cross-encoder 리랭커로 top-5. 외부 임베딩(B)은 함정 2개 — (1) 색인·질의 동일 모델 강제 → 질의마다 외부 왕복 + 외부 장애 = 검색 전면 중단, 폴백하려면 두 벌 색인 (2) 모델 은퇴 시 전체 재색인이 공급자 일정에 묶임. 게다가 대상이 내부 문서 |

#### ⑧ 관련 — 외부 LLM 을 쓰는 자리

| 용도 | 외부 LLM | 이유 |
|---|---|---|
| Q&A 생성(2편) · 신뢰도 검증(3편) | **적합** | 배치. 지연 무관, 품질이 곧 자산 |
| 리랭킹 | 조건부 | 질의마다 호출 → 지연·비용·장애 반경 |
| **임베딩** | **비권장** | 색인에 영구히 묶임 |
| 서빙 생성 | 조건부 | EC2 GPU 본선, 관리형은 비용 대안 |

원칙: **배치에는 외부 좋은 모델, 질의 경로와 색인에는 통제 가능한 로컬 모델.**
외부 품질은 사전생성 Q&A 안에 응고되어 자산으로 남는다.

교체 판단 기준(3편 골든셋 Recall 기준): `-3%p 이내` 로컬 유지 / `-3~-10%p` 리랭커 교체·튜닝 / `-10%p 초과` 외부 검토.
필수 이음매: 임베딩 호출 인터페이스화 · 벡터에 모델명·차원 태그 · 임계값 설정 분리 · 재색인 스크립트 1일차.

#### ⑧ 파생 — GPU 층 분리

임베딩·리랭커는 **질의마다** 도므로 상주 필요. "GPU 는 miss 때만 논다"는 진단은 절반만 맞음.

| 층 | 무엇 | 어디 |
|---|---|---|
| 상시 (작은 GPU) | 질문 임베딩 + 리랭커 | 작은 상주 인스턴스 |
| 간헐 (큰 GPU) | 대량 생성 배치 | Spot, 배치 시간만 |
| 간헐 (선택) | fallback 답변 생성 | 위와 공유 또는 관리형 |

#### 부가

- Codex OAuth(ChatGPT 구독) 대량 배치 호출 — 레이트리밋 + 약관 회색. "무한 생성"과 정면 충돌
- EC2 GPU 상주 비용 — g5.xlarge 온디맨드 시간당 $1 선 → 월 $700 대. miss 때만 쓰는데 상주비는 그대로

### 보정안: 8.5 / 10 — 적합

①②③ 반영 시 8점 초과. ④~⑦ 은 운영 품질 이슈로 시리즈 내에서 해소.
**단 8.5 는 조건부** — ⑧ 임베딩 측정(3편 골든셋)을 실제로 통과했을 때의 점수. 생략하면 ①③의 임계값이 숫자만 그럴듯한 채 작동하지 않음.
**판정: 조건부 통과. 방법론 시리즈 작성 진행.**
