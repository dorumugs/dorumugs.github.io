# 학군 지도 — 설계

작성일: 2026-07-27
상태: 승인됨
선행 문서: `2026-07-26-real-estate-dashboard-ui-design.md` (실거래 대시보드)

## 배경

`/real-estate/` 허브의 두 번째 도구다. 실거래 대시보드가 "어디가 얼마인가"를
답했고, 이건 "이 학교 근처 집은 얼마인가"를 답한다.

바탕이 된 글이 이미 다섯 편 있다 (`finance` 카테고리):

- 학군지 시리즈 3편 — 대치·목동·중계 / 1기신도시 / 신흥도심.
  학원가를 기준으로 **단지별 실거래가를 비교**하는 글이다.
- 중학교 코스 2편 — 일반중·국제중·사립중 프레임, 그리고 실제 학교 지도.
  "이름값이 아니라 우리 집 통학·성향으로 읽는 학교 지도"를 표방하고
  마지막 절이 **"위치로 역산하기"** 다.

두 시리즈 모두 학교와 시세를 같이 놓고 본다. 이 도구는 그 작업을 손으로 하지
않게 만든다.

## 목표

`/real-estate/schools/` 에서 서울·경기의 **사립초와 상위권 중학교**를 지도에
올리고, 학교를 누르면 그 학교가 속한 법정동의 아파트 실거래 시세를 보여준다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 핵심 질문 | **이 학교 근처 집은 얼마인가** (역산) |
| 지역 범위 | **서울·경기만** |
| '근처'의 정의 | **같은 법정동** (지오코딩 없음) |
| 지도 | 실거래 대시보드의 `map.svg` 를 그대로 재사용 |
| 초등학교 | **사립초만** |
| 중학교 | **특목고·자사고 진학 비율 상위만** |
| 고등학교 | **다루지 않는다** |
| 진입 흐름 | 걸러진 학교를 **처음부터 전부** 지도에 뿌린다 |

### 학교를 걸러내는 이유와 그 결과

"떨어지는 학교는 다 걸러내고 싶다"가 요구사항이다. 학교급마다 쓸 수 있는 지표가
달라서 기준을 따로 둔다.

- **초등학교 — 사립초만.** 설립구분이 위치 데이터에 이미 있어 **추가 키 없이
  오늘 된다.**
- **중학교 — 특목고·자사고 진학 비율.** 학군 논의에서 사실상 표준으로 쓰는
  지표다. 학교알리미가 필요하다.

**고등학교는 다루지 않는다.** 평준화 지역은 배정이라 집과 연결이 약하고,
자사고·특목고는 광역·전국 단위 모집이라 근처에 살 이유가 없다 —
"이 학교 근처 집은 얼마인가"라는 이 도구의 질문 자체가 성립하지 않는다.
덤으로 고교 유형(자사고·외고·과학고)은 위치 데이터에 없어 판별에 별도 소스가
필요했는데, 그 의존이 통째로 사라진다.

### 실측 (2026-07-27, 키 등록 후 전수 조회)

전국 12,011개 중 서울·경기는 **3,871개**다.

| 학교급 | 공립 | 사립 | 국립 |
|---|---:|---:|---:|
| 초등학교 | 1,942 | **41** | 2 |
| 중학교 | 873 | 197 | 2 |
| 고등학교 | 474 | 337 | 3 |

**좌표 결측은 0건이다.** 위경도가 전부 채워져 있다.

걸러낸 결과는 **사립초 41개 + 중학교 상위 20% 214개 = 255개**다. 3,871개를
전부 뿌릴 수는 없지만 255개는 **처음부터 한 화면에 뿌릴 수 있다.** 어디에 몰려
있는지가 한눈에 보이는 게 이 도구의 핵심 가치다.

국립초 2곳(서울대 사대부초 등)은 선발 성격이 사립초와 비슷하지만, 요구사항이
"사립초"였으므로 넣지 않는다. 넣기로 하면 필터 조건 한 줄이다.

### '좋은 학교' 라고 쓰지 않는다

특목고 진학률은 학교 자체의 기여와 동네 배경(소득·사교육 밀도)을 구분하지
못한다. 집을 고르는 도구라는 맥락에서는 둘이 섞인 값이 오히려 맞는 신호지만
— 어차피 동네를 통째로 사는 것이므로 — 화면에는 **지표 이름을 그대로**
("특목고·자사고 진학 비율") 적고 "좋은 학교"라는 표현은 쓰지 않는다.

### 서울·경기만 하는 이유

실거래 데이터가 서울·경기뿐이다. 다른 지역 학교를 올려도 옆에 붙일 시세가 없다.
수집 단계에서 시도교육청 코드로 걸러 나머지는 저장조차 하지 않는다.

### '같은 법정동' 으로 정한 이유

진짜 반경(500m/1km)을 재려면 단지 좌표가 필요한데, **단지 마스터에는 좌표가
없다** (PNU 와 주소만 있다). 전국 아파트 단지 좌표를 한 번에 주는 공개 데이터셋도
없어서, 5천~2만 건을 지오코딩 API 로 변환해 캐시해야 한다 — 키를 하나 더 신청하고
1회성 배치를 만드는 비용이다.

반면 **좌표 없이 되는 길이 이미 있다.** 학교 위치 데이터에 지번주소가 있고,
구별 JSON 의 단지에는 `dong`(법정동) 필드가 이미 들어 있다. 둘을 법정동으로 맞추면
지오코딩이 필요 없다. 실측으로 확인한 조인 경로다:

```
regions.dong_code('11680', '대치동') -> 1168010600
regions.dong_code('11470', '목동')   -> 1147010200
regions.dong_code('41135', '서현동') -> 4113510500
```

대치동처럼 넓은 동은 '근처'라기엔 성기다. 그 사실을 화면에 명시해 오해를 막고,
반경이 필요해지면 그때 좌표를 붙인다. 설계를 반경으로 교체하기 쉬운 모양으로
잡아 둔다 — 근접 판정을 한 함수에 가둔다.

## 데이터

### 출처와 접근 권한

| 데이터셋 | 출처 | 쓰임 |
|---|---|---|
| 전국초중등학교위치표준데이터 | data.go.kr `tn_pubr_public_elesch_mskul_lc_api` | 학교 위치·설립구분 — **필수** |
| 학교알리미 졸업생의 진로 현황 | schoolinfo.go.kr `openApi.do` | 중학교 진학 비율 — **필수** |
| 전국중학교학교군표준데이터 | data.go.kr `tn_pubr_public_mskul_atndskl_zn_api` | 범위 밖 |
| 전국학교학구도연계정보표준데이터 | data.go.kr `tn_pubr_public_schul_atndskl_zn_drw_lnkinfo_api` | 범위 밖 |

**키가 둘이다.** 위치 데이터는 data.go.kr 키(실거래와 같은 키, 단 데이터셋별
활용신청 필요), 진학 현황은 **학교알리미 자체 키**로 별개다.

**위치 데이터는 2026-07-27 활용신청이 승인돼 지금 키로 정상 조회된다**
(`resultCode 00 NORMAL_SERVICE`, 전국 12,011건 전수 확인). 학교알리미 키는 아직
발급받지 않았다 — 2단계에서 필요하다.

미등록 데이터셋은 `resultCode 30 = SERVICE KEY IS NOT REGISTERED` 를 돌려주고,
존재하지 않는 서비스는 `12` 를 돌려준다. 둘을 구분해 안내 메시지를 다르게 낸다.

### 응답 필드 (실측)

```
schoolId, schoolNm, schoolSe(초등학교/중학교/고등학교), fondDate,
fondType(공립/사립/국립), bnhhSe(본교/분교), operSttus(운영),
lnmadr(지번주소), rdnmadr(도로명주소), cddcCode, cddcNm(시도교육청),
edcSport, edcSportNm(교육지원청), creatDate, changeDate,
latitude, longitude, referenceDate, insttCode, insttNm
```

`numOfRows=1000` 으로 13번 부르면 전국이 다 온다. 서울·경기 필터는 `lnmadr` 접두사
(`서울특별시` / `경기도`)로 거른다 — `cddcNm` 도 쓸 수 있지만 주소가 법정동 조인에
어차피 필요하므로 한 곳만 본다.
data.go.kr 에서 데이터셋별로 활용신청이 필요하다. 표준데이터는 보통 자동승인이다.

### 두 단계로 나눠 낸다

키 두 개를 다 기다릴 필요가 없다. **사립초 필터는 위치 데이터만으로 완결된다** —
설립구분이 거기 들어 있다.

| 단계 | 내용 | 필요한 키 | 상태 |
|---|---|---|---|
| 1 | 사립초 41개 지도 + 법정동 시세 | data.go.kr (위치) | **확보됨** |
| 2 | 상위권 중학교 214개 추가 | + 학교알리미 | 미발급 |

1단계만으로도 쓸 수 있는 화면이 나오고, 2단계는 점 레이어에 학교급 하나가
늘어나는 것이다. 학교알리미 키 발급이 늦어져도 작업이 막히지 않는다.

### 학업성취도는 못 구한다

2017년부터 국가수준 학업성취도 평가가 전수에서 표집으로 바뀌어 **학교별 성적은
공개되지 않는다.** 사설 사이트의 "학교 순위"도 대부분 진학 현황을 가공한 것이다.
그래서 중학교 기준을 진학 비율로 잡았다.

### 학구도 데이터로는 배정을 못 푼다

`전국학교학구도연계정보표준데이터` 를 확인한 결과 필드가 학구ID·학교ID·학교명·
학교급·교육청코드뿐이고 **경계 도형이 없다.** 주소나 행정동 코드로 통학구역을
매핑해 주지 않는다. "이 아파트는 어느 학교로 배정되나"를 정확히 답할 수 없는
이유이고, 역산 방향을 고른 근거이기도 하다.

### 위치 데이터에 없는 것

학교명·학교급·설립구분(공/사립)·본분교·운영상태·지번주소·도로명주소·교육청·
위도·경도가 전부다. **진학률도 학업성취도도 없다.** 사립초 필터는 설립구분으로
되지만, 중학교 기준은 학교알리미에서 따로 가져와야 하는 이유다.

## 아키텍처

```
[학교위치 표준데이터]        scripts/collect_schools.py
  서울·경기 초·중          →  data/schools.csv.gz      (위치·설립구분)

[학교알리미 진로 현황]       scripts/collect_progression.py
  서울·경기 중학교          →  data/school_progression.csv.gz
                                          │
data/geo/projection.json ──────────────┤  scripts/build_schools.py
  (build_geo.py 가 내보낸 투영 파라미터)  │  필터 + 위경도→SVG 좌표 + 법정동 조인
                                          ▼
                        assets/realestate/schools.json  (걸러진 250~350개 전부)
                                          │
                                          ▼
              _pages/real-estate-schools.md  →  /real-estate/schools/
```

원본 → 집계 → 표현 3단 분리는 실거래 때와 같다.

**구별로 쪼개지 않는다.** 걸러낸 학교가 300개 안팎이라 한 파일에 다 들어간다
(예상 40KB 내외). 실거래 대시보드가 구별 lazy load 를 쓴 건 단지가 구당
수만 건이어서였다. 여기서는 그럴 이유가 없고, 한 번에 받아야 전체 분포를
첫 화면에 뿌릴 수 있다.

### 투영 공유 — 이 설계의 유일한 까다로운 지점

학교 점을 기존 지도에 얹으려면 **`build_geo.py` 와 완전히 같은 투영**을 써야 한다.
지금 `build_geo.py` 의 `project()` 는 `min_lon`, `max_lat`, `k`, `span_x`, `span_y` 를
내부에서 계산하고 버린다.

`data/geo/projection.json` 으로 내보내도록 고친다.

```json
{"min_lon": 126.xxx, "max_lat": 38.xxx, "k": 0.79xxx,
 "span_x": 1.xxx, "span_y": 1.xxx, "width": 1000.0, "height": 1201.x}
```

`build_schools.py` 는 이 파일만 읽어 같은 식으로 변환한다.

```
x = (lon - min_lon) * k / span_x * width
y = (max_lat - lat) / span_y * height
```

파라미터를 각자 계산하면 경계 데이터나 `--eps` 를 갱신할 때 학교 점이 조용히
어긋난다. 한 곳에서만 정의하고 나머지는 읽기만 한다.

`build_geo.py` 변경은 파일 하나를 더 쓰는 것뿐이다. **`map.svg` 는 재생성해도
바이트가 동일해야 한다** — 회귀 확인 항목이다.

### 법정동 조인

학교 지번주소에서 시군구와 읍면동 이름을 뽑아 `regions.dong_code()` 로 10자리
법정동 코드를 만든다. 구별 JSON 의 단지 `dong` 도 같은 함수로 코드화해 맞춘다.
이름 문자열로 직접 비교하지 않는다 — 같은 이름의 동이 다른 구에 있다.

조인 실패율을 로그로 남기고 **10% 를 넘으면 빌드를 실패시킨다.** 실거래 때
화성시 단지 마스터가 통째로 비어 있는 걸 늦게 발견한 전례가 있다.

## 출력 포맷

### `assets/realestate/schools.json`

걸러진 학교 전부를 한 파일에 담는다.

```json
{"generated": "2026-07-27",
 "cutoff": {"mid_pct": 20.0, "year": "2025"},
 "schools": [
   {"name": "대치중학교", "lvl": "중", "sgg": "11680",
    "dong": "대치동", "dong_cd": "1168010600",
    "addr": "서울특별시 강남구 대치동 ...",
    "x": 512.3, "y": 641.8,
    "adv": {"n": 312, "special": 41, "pct": 13.1}},
   {"name": "계성초등학교", "lvl": "초", "found": "사립", "sgg": "11650",
    "dong": "내곡동", "dong_cd": "1165010800",
    "addr": "서울특별시 서초구 ...",
    "x": 498.1, "y": 702.4}
 ]}
```

- `x`/`y` 는 `map.svg` 의 viewBox 좌표. 소수점 한 자리로 고정해 결정론을 지킨다
- `adv` 는 중학교에만 붙는다: 졸업생 수, 특목고·자사고 진학자 수, 비율(%)
- `found` 는 초등학교에만 붙는다 (사립초만 남기므로 값은 항상 `"사립"` 이지만,
  필터가 실제로 걸렸는지 눈으로 확인할 수 있게 남긴다)
- `cutoff` 는 중학교를 어디서 잘랐는지 기록한다. 화면에 그대로 표시해 기준을
  숨기지 않는다

```
│   지도           │  대치중학교        │

│   전부 점으로)    │  특목·자사 진학 13.1%
│                 │  (졸업 312명 중 41명)
│                 │  ──────────────   │
│                 │  대치동 아파트 시세  │
└─────────────────┴──────────────────┘
        같은 법정동 단지 표 (전체 폭)
```

- **첫 화면에 걸러진 학교가 전부 뜬다.** 어디에 몰려 있는지가 이 도구의 핵심이다.
  구 채색은 하지 않는다 — 점이 이미 밀도를 보여준다
- 학교급 토글(사립초 / 중학교)과 중학교 상위 비율 슬라이더로 점을 걸러낸다
- 상위 비율은 **10 / 20 / 30% 와 전체**를 고를 수 있다. 기본 20%
- 학교를 누르면 오른쪽에 학교 정보와 진학 지표, 아래에 그 법정동 단지 표가 나온다
- 단지 표는 실거래 대시보드의 구별 JSON 을 그대로 읽는다. 새 집계가 없다
- 점이 겹치는 곳(대치동 등)은 선택된 점을 표면색 링으로 둘러 위로 올린다

### 오해를 막는 문구

화면에 **"같은 법정동 기준입니다. 실제 배정 학교는 통학구역에 따라 다릅니다"** 를
상시 표시한다. 이걸 안 달면 배정표로 읽힌다.

**사립초와 국제중·사립중은 배정이 아니라 지원**이라 '근처'의 의미가 또 다르다.
학교급 옆에 설립구분을 함께 적어 구분되게 한다.

지표 이름은 **"특목고·자사고 진학 비율"** 로 그대로 쓰고, 어느 해 졸업생 기준인지와
상위 몇 %로 잘랐는지를 화면에 적는다. "좋은 학교", "학군 순위" 같은 표현은 쓰지
않는다 — 이 값이 재는 것보다 넓은 주장을 하게 된다.

### 모바일 390px

실거래 대시보드와 같다. 2단이 세로로 접히고 표는 `overflow-x: auto` 안에 들어간다.
`_dev/tools/check_mobile.py` 로 `[click]`·`[tooltip]` 양쪽을 확인한다.

### URL 파라미터

`/real-estate/schools/?view=seoul&lvl=중&top=20&school=<학교명>`

글에서 특정 학교 화면을 바로 가리킬 수 있게 한다. 실거래 대시보드와 같은 규칙이고,
잘못된 값은 무시하고 기본값으로 떨어진다.

## 재사용

`map.js`, `palette.js`, `data.js`, `dashboard.css` 를 그대로 쓴다. 새로 만드는 것은
학교 점 레이어와 패널 렌더러뿐이다.

실거래 대시보드의 동작은 바뀌지 않는다. `build_geo.py` 만 파일 하나를 더 쓰도록
바뀌고, 그 결과 `map.svg` 가 재생성되지만 **바이트가 같아야 한다.**

## 색

`palette.js` 를 그대로 쓴다. 새 색을 만들지 않는다.

- 학교 점: 사립초와 중학교 2종을 범주형 앞 두 칸(파랑 `#2a78d6`, 주황 `#eb6834`)
  으로. 두 색은 색맹 대비 검증을 통과한 조합이고, 2종이라 모든 판정에 여유가 있다
- 구는 채색하지 않는다. 점이 이미 밀도를 보여주므로 배경은 옅은 회색 한 톤으로
  두어 점이 묻히지 않게 한다
- 점 크기는 8px 이상, 선택된 점은 표면색 링으로 둘러 겹침에서 구분한다

학교급은 점 색만으로 구분하지 않는다 — 범례를 상시 두고, 툴팁과 패널에 학교급을
글자로 넣는다.

## 검증

- **투영 일치**: 알려진 좌표(서울시청 `37.5663, 126.9779`)를 두 스크립트가 같은
  SVG 좌표로 변환하는지. `map.svg` 재생성 후 바이트 동일
- **점이 지도 안에 있는지**: 모든 학교의 `x`/`y` 가 viewBox(`0..1000`, `0..1201`)
  범위 안. 하나라도 벗어나면 투영이 틀어진 것이므로 빌드 실패
- **법정동 조인**: 실패율 10% 미만. 대치동·목동·중계동·서현동은 반드시 성공
- **필터**: 사립초 결과에 공립이 하나도 섞이지 않을 것. 중학교 상위 20% 결과
  개수가 전체 중학교의 20%±1 일 것
- **결정론**: 같은 입력으로 두 번 빌드해 JSON 바이트 동일. 동점 학교의 정렬이
  흔들리지 않도록 정렬 키를 완전 전순서로 둘 것 (비율 → 학교명 → 시군구)
- **크기 예산**: `schools.json` 100KB 이하
- **모바일**: 390px 에서 `scrollWidth <= 390`, `[click]`·`[tooltip]` 양쪽 합격
- **키 미등록 처리**: `resultCode 30` 을 "활용신청이 필요합니다" 로 안내하고
  정상 종료. 다른 오류와 구분해 메시지를 다르게 낼 것
