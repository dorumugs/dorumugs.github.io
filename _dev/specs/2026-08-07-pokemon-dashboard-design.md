# 포켓몬 카드 가격 대시보드 + Dashboard 허브 이전 설계

작성 2026-08-07

## 왜 만드는가

2026-08-07 에 발행한 「포켓몬 카드 수집과 투자」 5부작에서, 시장이 인용하는
"20년간 3,821%" 지수를 근거로 못 쓴다고 썼다. 이유는 세 가지였다.

- 구성 종목과 가중치가 공개되지 않는다
- 살아남은 카드만 세는 생존편향이 걷히지 않았다
- 왕복 비용(감정·수수료·세금)이 반영되지 않았다

깠으면 대안을 내야 한다. 이 대시보드는 그 대안이다. **구성·가중치·산식을
전부 공개한 지수**를 매일 갱신한다. 남의 지수를 다시 인용하지 않고 원가격에서
직접 만든다.

동시에 `/real-estate/` 허브를 `/dashboard/` 로 승격한다. 부동산 도구 모음이
아니라 여러 대시보드가 들어가는 자리로 성격이 바뀐다.

## 1. 데이터 소스

**TCGdex** (`https://api.tcgdex.net/v2/en/`) 를 쓴다. API 키가 필요 없고 매일
갱신된다.

pokemontcg.io 는 후보에서 뺐다. Scrydex 로 편입된 뒤 `api.pokemontcg.io/v2`
가 HTTP 500 을 반환한다 (2026-08-07 실측).

### 실측한 응답 형태

`GET /v2/en/cards/base1-4` 의 `pricing` 필드:

| 소스 | 통화 | 필드 |
|---|---|---|
| cardmarket | EUR | `avg` `low` `trend` `avg1` `avg7` `avg30` (+ `-holo` 변종) |
| tcgplayer | USD | variant(`holofoil`/`normal`/`reverseHolofoil`)별 `lowPrice` `midPrice` `highPrice` `marketPrice` `directLowPrice` |

양쪽 다 `updated` 타임스탬프를 준다.

### 알아낸 제약

**세트 목록에는 가격이 없다.** `/sets/{id}` 응답의 카드 배열은
`id` `image` `localId` `name` 뿐이다. 가격은 **카드 1장당 1요청**이다.

**처리량 실측** (2026-08-07, 60장 표본):

| 동시 요청 | 처리량 | 20,656장 환산 |
|---|---|---|
| 1 | 1.1 req/s | 약 5시간 |
| 4 | 4.4 req/s | 약 78분 |
| 8 | 8.6 req/s | 약 40분 |

무료 API 이므로 **동시 4** 로 고정한다. 40분으로 줄이자고 8을 쓸 이유가 없다.

**가격 커버리지가 세트 유형에 따라 갈린다.** 14개 세트 표본 조사 결과:

| 세트 유형 | 예시 | 커버리지 |
|---|---|---|
| 정규 확장팩 | Neo Discovery, Flashfire, Burning Shadows, Phantasmal Flames | 100% |
| 프로모·트레이너킷·서브컬렉션 | Black Star Promos, DP Trainer Kit, Unown Collection | 0% |

이건 제약이 아니라 이득이다. 프로모는 유통 경로가 불규칙해서 어차피 지수
종목으로 부적합하다. **유니버스를 정규 확장팩으로 한정**하면 결측 구멍이 사라진다.

### 모집단

| 구분 | 세트 | 카드 |
|---|---|---|
| 전체 | 218 | 23,444 |
| 정규 확장팩 | 162 | 20,656 |
| 제외(프로모·킷·컬렉션) | 56 | 2,788 |

시대별 정규 확장팩 카드 수:

| 시대 | 카드 |
|---|---|
| 빈티지 1999–2003 | 1,825 |
| 클래식 2004–2010 | 3,201 |
| 모던 2011–2019 | 5,724 |
| 최신 2020– | 9,906 |

### 정규 확장팩 판정

이름 정규식(`promo|trainer kit|collection|deck|tin|box|kit|misc|jumbo|energy`)은
**1차 프리필터일 뿐**이다. 최종 판정 기준은 **가격 커버리지 실측치**다.
전수 스캔 후 세트별로 `pricing.tcgplayer` 가 있는 카드 비율을 재고,
**80% 이상인 세트만** 유니버스 모집단에 넣는다. 정규식이 잘못 걸러낸 세트가
있으면 이 단계에서 되살아난다.

판정 결과는 `data/pokemon/sets.json` 에 남겨 왜 포함/제외됐는지 추적 가능하게 한다.

## 2. 지수 설계

### 층 구조

시대 4 × 가격대 3 = **12칸**. 각 칸에서 고정 표본을 뽑는다.

| 축 | 구간 |
|---|---|
| 시대 | 빈티지(1999–2003) · 클래식(2004–2010) · 모던(2011–2019) · 최신(2020–) |
| 가격대 | 고가 · 중가 · 저가 |

가격대 경계는 **시대 안에서** 전수 스캔 가격 분포의 3분위로 잡는다. 시대를
가로질러 절대 금액으로 자르면 빈티지가 전부 고가, 최신이 전부 저가가 되어
칸이 무너진다.

칸당 표본 **25장**, 총 **300장**. 매일 300요청이면 동시 4로 약 70초다.

표본 추출은 각 칸에서 시가 상위 편중을 피하도록 **가격 분위별 균등 추출**한다
(칸 안에서 다시 5분위로 나눠 각 5장). 난수 시드는 `data/pokemon/universe.json`
에 기록해 재현 가능하게 한다.

### 산식

칸 $c$ 의 표본 $n_c$ 장, 카드 $i$ 의 $t$ 일 가격 $P_{i,t}$, 기준일 가격 $P_{i,0}$ 일 때

$$I_t = 100 \times \sum_{c=1}^{12} w_c \cdot \frac{1}{n_c} \sum_{i \in c} \frac{P_{i,t}}{P_{i,0}}$$

가중치는 **12칸 균등** $w_c = 1/12$ 로 시작한다.

**수식이 어려우면 이렇게 읽으면 된다.** 카드마다 "기준일에 견줘 지금 몇 배냐"를
구한다. 기준일에 100달러였던 게 지금 120달러면 1.2배다. 이 배수를 칸 안에서
평균 내면 그 칸의 성적이 나온다. 칸 12개 성적을 다시 평균 내고 100을 곱하면
지수다. 처음이 100이고, 120이 되면 시장이 20% 올랐다는 뜻이다.

균등가중을 고른 이유는 **조작 여지가 가장 적어서**다. 시장 규모 비례가 이론적으로
낫지만, 포켓몬 카드는 유통 물량이 공개되지 않아 "시장 규모"를 누구도 모른다.
모르는 걸 아는 척 가중치에 넣으면 그게 바로 우리가 깐 짓이 된다.

### 하위지수

메인 지수 하나로는 "어디가 올랐나"를 못 본다. 같은 산식으로 하위지수를 낸다.

- 시대별 4개 (칸 3개씩 균등)
- 가격대별 3개 (칸 4개씩 균등)

### 기준일과 소급 구간

기준일은 **첫 수집일 = 100**. 장기 시계열을 무료로 주는 데는 없으므로 진짜
추이는 이 날부터 쌓인다.

다만 Cardmarket 이 `avg7`/`avg30` 을 주므로 **30일 소급 곡선을 추정**할 수 있다.
이 구간은 반드시 **점선 + "추정" 라벨**로 그린다. `avg30` 은 "30일 전 가격"이
아니라 "30일 평균"이므로 실제 경로와 다르다. 이걸 실선으로 그리면 우리가 깐
지수와 똑같은 짓을 하는 것이다.

### 생존편향 처리

이게 5부작에서 지적한 핵심이므로 명시적으로 다룬다.

- 표본은 **6개월 고정**. 중간에 오른 카드로 갈아타지 않는다.
- 가격이 결측되면 마지막 값을 **최대 7일** 이월한다. 그 뒤로도 없으면 결측 처리하고, 그 카드는 칸 평균에서 제외하되 **제외 사실을 대시보드에 표시**한다.
- 리밸런싱(6개월) 때 빠진 카드도 `data/pokemon/universe_history.json` 에 남긴다. 과거 지수를 소급 수정하지 않는다.

**리밸런싱 구현은 1차 범위에서 뺀다.** 첫 리밸런싱 시점이 2027-02 라 지금
만들 이유가 없다. 대신 `universe.json` 에 `base_date` 와 `seed` 를 남겨 두어
그때 이력 파일을 붙일 수 있게 한다.

### 공개 원칙

대시보드에 다음을 전부 노출한다. 하나라도 빠지면 이 프로젝트의 존재 이유가 없다.

- 구성 종목 300장 전체 목록 (카드명·세트·시대·가격대·현재가)
- 가중치와 산식
- 리밸런싱 이력
- 결측·제외 카드 수
- 마지막 갱신 시각

### 리다이렉트

`jekyll-redirect-from` 은 이 저장소에 없다(`_config.yml` 플러그인 화이트리스트
5개뿐). **플러그인을 추가하지 않는다.** `_config.yml` 은 사이트 전역 설정이라
건드릴 이유가 없다.

대신 옛 주소를 `permalink` 로 갖는 stub 페이지 3개를 만든다. `_layouts/redirect.html`
을 새로 두고 meta refresh + `rel="canonical"` + 본문 안내 링크를 넣는다.
`jekyll-redirect-from` 이 하는 일이 정확히 이것이다.

테마 원본 `_layouts/` 를 건드리지 말라는 규칙이 있으나, 이건 **원본 파일 수정이
아니라 신규 파일 추가**이므로 규칙에 걸리지 않는다.

### 링크 정리

`/real-estate/` 를 가리키는 곳은 8군데이고 **전부 `_pages/` 와
`_data/navigation.yml` 안에 있다. 발행된 글(`_posts/`) 에는 하나도 없다.**
검색 유입 리스크가 낮다.

### 허브 페이지

`/dashboard/` 는 섹션 둘로 나눈다.

- **부동산** — 실거래 · 학군 · 재개발재건축
- **수집품** — 포켓몬 카드 지수

기존 `hub.css` 의 카드 그리드를 그대로 쓰고 섹션 제목만 추가한다.

## 4. 파이프라인

기존 규칙을 그대로 따른다. 표준 라이브러리만 쓴다(`urllib`, `csv`, `gzip`, `json`).

| 파일 | 역할 |
|---|---|
| `scripts/tcgdex_api.py` | 순수 함수. 응답 파싱·가격 정규화·층화추출·지수 계산. I/O 없음 |
| `scripts/collect_pokemon.py` | I/O·예산·상태 재개. `--max-calls` 로 하루 예산을 끊는다 |
| `scripts/build_pokemon.py` | 집계. `assets/pokemon/*.json` 생성 |
| `scripts/pokemon_daily.sh` | 크론 진입점 |

### 수집 2단계

**1단계 전수 스캔(1회성).** 정규 확장팩 후보 20,656장의 가격을 훑어 분포를
확보한다. `--max-calls 6000` 기본값으로 4일에 나눠 돌린다. 중단 지점은
`data/pokemon/scan_state.json` 에 남겨 다음 실행에서 이어받는다.

동시 4로 78분이면 하룻밤에 다 되지만 나눠 돈다. 무료 API 를 한 번에 2만 번
두들길 이유가 없고, 부동산 수집기가 이미 같은 방식이라 운영이 일관된다.

**2단계 상시 갱신.** 유니버스 300장만 매일 긁는다. 약 70초.

### 저장

`data/pokemon/prices.csv.gz` 에 append-only 로 쌓는다.

| 컬럼 | |
|---|---|
| `date` `card_id` `variant` | 키 |
| `tp_market` `tp_low` `tp_mid` | TCGplayer USD |
| `cm_avg` `cm_trend` `cm_avg7` `cm_avg30` | Cardmarket EUR |

gzip 은 `mtime=0` 으로 고정한다. 안 그러면 내용이 같아도 매일 새 blob 이 쌓인다.

하루 300행이면 1년에 11만 행이다. gzip 으로 수 MB 수준이라 저장소에 부담이 없다.

### 산출물

`assets/pokemon/` 아래:

| 파일 | 내용 |
|---|---|
| `index.json` | 메인 지수 + 하위지수 7개 시계열 |
| `universe.json` | 구성 종목 300장 (카드명·세트·시대·가격대·현재가·기준가) |

| TCGdex 가 무료 정책을 바꾸거나 죽는다 | 파싱을 `tcgdex_api.py` 에 격리했으므로 소스 교체 시 이 파일만 바꾼다. fixtures 가 회귀를 잡는다 |
| 가격 커버리지가 세트별로 달라진다 | 80% 임계로 세트를 거르고, 결측률을 대시보드에 노출한다 |
| 0일차라 추이가 없다 | 30일 소급 추정 곡선을 점선으로 제공. 실선은 실측분만 |
| 표본 300장이 시장을 대표 못 한다 | 대표성을 주장하지 않는다. 구성을 전부 공개하고 "이 300장의 성적"이라고 명시한다 |
| 옛 URL 유입이 끊긴다 | stub 리다이렉트 3개 + canonical |

## 범위 밖

- 국내 원화 시세 (공개 API 없음)
- 일본판·중국판 시세
- 개별 카드 검색·워치리스트
- PSA 등급별 가격 (PSA 인구 보고서는 별도 소스이고 API 가 없다)
- 왕복 비용 계산기

5부작에서 왕복 비용을 강조했으므로 계산기가 어울리지만, 지수를 먼저 세우고
데이터가 쌓인 뒤에 붙이는 게 맞다.
