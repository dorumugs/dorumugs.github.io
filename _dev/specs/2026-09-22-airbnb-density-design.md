# 전국 Airbnb 밀집도 지도 — 설계

작성 2026-09-22. 대상 페이지 `/dashboard/airbnb/`.

airbnb.co.kr 지도검색 화면을 지역별로 훑어 숙소 위치를 모으고, 전국 어디에
Airbnb 가 몰려 있는지 지도에 보여준다.

## 1. 스파이크에서 확인한 사실

전부 2026-09-22 실측이다. 추측이 아니라 이 숫자 위에 설계가 얹혀 있으므로,
동작이 이상하면 여기부터 다시 재라.

| 항목 | 실측값 |
|---|---|
| 좌표 위치 | SSR HTML 의 `<script id="data-deferred-state-0">` 안. `"Coordinate","latitude":37.4973,"longitude":127.0374` |
| 접근 방법 | `urllib` + 평범한 Chrome UA 로 **HTTP 200**. 헤드리스 브라우저 불필요 |
| 요청 URL | `https://www.airbnb.co.kr/s/homes?ne_lat=&ne_lng=&sw_lat=&sw_lng=&search_by_map=true&search_type=user_map_move` |
| 응답 크기 | 요청당 약 1MB(gzip 전송) |
| 페이지당 | 숙소 약 20건. 커서 페이지끼리 일부 중복 |
| bbox 당 상한 | 커서 15장. 중복 때문에 **실제 수집은 약 200건에서 멈춘다**. bbox 안에 712건이 있어도 나머지는 못 받는다 |
| 총건수 | HTML 에 `숙소 N개`. 단 **1,000 에서 잘린다** — 전국·서울·제주·부산 모두 `1,000` |
| bbox 준수 | 지킨다. 받은 좌표가 전부 bbox 내부였다 |
| robots.txt | `User-agent: *` 에 `Disallow: /s/*/*`. `/s/homes?…` 는 세그먼트가 하나라 **매칭되지 않는다** |

### 나중에 실측으로 확인한 것

**빈 bbox 는 파싱 고장과 응답이 똑같이 생겼다.** 동해 한복판·설악산 산속·서해
먼바다를 찔러 보니 셋 다 총건수 문구도 좌표도 없이 온다(HTML 629KB). 그래서
"모르면 쪼갠다" 규칙을 그대로 두면 바다에서 4^n 으로 터진다. `looks_empty()`
가 이 경계를 맡는다. 진짜 고장은 숙소가 확실히 있는 bbox(canary)로 따로 본다.

**leaf 판정은 숙소를 놓치지 않는다.** 제주시 도심의 leaf 크기 bbox(총건수 96)를
통째로 거둔 것과 넷으로 쪼개 거둔 것을 견줬다.

| | 좌표 | 호출 |
|---|---|---|
| 통째로 | 83 | 6 |
| 넷으로 쪼개서 | **83** | 7 |

같다. 임계값 180 이 맞다. 다만 양쪽에 13건씩(약 15%) 서로 다른 좌표가 있다 —
**Airbnb 가 같은 bbox 에 대해 매번 조금씩 다른 결과를 준다.** 밀집도를 보는
데는 문제가 없지만, 같은 지역을 두 번 수집해도 숫자가 딱 맞지는 않는다.

총건수 96 중 83 만 거둔 것은 누락이 아니다 — Airbnb 는 bbox 바깥 여백의 숙소도
결과에 섞어 주고, 우리가 `contains()` 로 걸러낸다.

**수집 속도는 호출당 약 12건이다.** 제주 전역 150콜에 1,823건이었다.

### 설계를 강제하는 두 가지

**bbox 상한 200건** 때문에 한 번의 요청으로 넓은 지역을 훑을 수 없다. 반드시
**쿼드트리 분할**이 필요하다 — 총건수가 상한을 넘으면 bbox 를 넷으로 쪼개
다시 묻는다.

**총건수가 1,000 에서 잘리므로** 총건수는 "분할이 필요한가"를 판정하는 데만
쓴다. 절대 집계값으로 쓰지 않는다. 최종 숫자는 **수집한 좌표를 세어서** 낸다.

## 2. 수집 예절과 공개 범위

robots.txt 는 이 경로를 막지 않지만 Airbnb 이용약관은 자동수집을 따로
금지한다. 그래서 다음을 지킨다. 이건 성능 조정 항목이 아니라 지켜야 할 선이다.

- 요청 간격 **2초 고정**. 병렬 요청 없음.
- 한 번 실행의 예산을 `--max-calls` 로 끊는다. 기본 1,200콜(약 45분).
- 4xx/5xx 가 연속 5회 나오면 **그 실행을 접는다**. 재시도로 밀어붙이지 않는다.
- **좌표 말고는 아무것도 저장하지 않는다.** 응답에는 숙소 ID·이름·가격·사진이
  다 들어 있지만 파서가 좌표만 꺼낸다(`parse_coordinates`). 안 모으니 샐 것도
  없고, 숙소 콘텐츠를 재배포하는 모양이 되지 않는다. 목적이 밀집도라 좌표면
  충분하다.
- Airbnb 가 주는 좌표 자체가 이미 정확한 주소가 아닌 근사 좌표다.

### 3.1 수집 상태

`data/airbnb/state.json.gz` 하나에 모아 둔다. 크론이 중간에 죽어도 다음
실행이 이어받는다. **50콜마다 저장한다** — 마지막에 한 번만 쓰면 40분짜리
실행이 중간에 죽을 때 모은 것이 통째로 날아가고, 다시 모으려면 같은 시간만큼
남의 서버를 또 두드려야 한다.

| 키 | 내용 |
|---|---|
| `frontier` | 아직 안 본 bbox 목록. `[ne_lat, ne_lng, sw_lat, sw_lng]` |
| `points` | **확정 스냅샷.** 지난 바퀴를 끝까지 다 돈 결과. 화면에 나가는 건 이쪽 |
| `pending` | 지금 돌고 있는 바퀴가 모으는 중인 좌표. 다 돌면 `points` 를 대신한다 |
| `weak` / `weak_pending` | 상한에 걸려 덜 걷힌 leaf bbox. 위 둘과 짝이다 |
| `stats` | leaf 수, 분할 수, 빈칸 수, 덜걷힘 수, 누적 호출 수 |
| `updated` / `completed_at` | 마지막 실행 시각 / 마지막으로 한 바퀴를 다 돈 시각 |

### 왜 `points` 와 `pending` 을 가르나

전국 한 바퀴에 며칠이 걸린다. 한 통에 담고 바퀴마다 비우면 그 며칠 동안
지도가 반쯤 빈 채로 보이고, 비우지 않으면 없어진 숙소가 영원히 남는다.
그래서 **모으는 건 `pending` 에, 보여주는 건 `points` 에서** 한다. 다 돌면
`pending` 이 `points` 를 대신한다(`finish_pass`).

빈 바퀴는 갈아 끼우지 않는다 — 수집이 통째로 깨진 바퀴가 지도를 지우는 것보다
지난 바퀴 지도가 남는 편이 낫다.

첫 바퀴를 아직 못 끝냈으면 `pending` 이라도 보여준다(`published_points`).
그러지 않으면 처음 며칠 동안 화면이 통째로 빈다. 그때는 화면이 "아직 전국을
한 바퀴 다 돌지 못했습니다" 라고 스스로 밝힌다.

### 3.2 쿼드트리

### 어디서 시작하나

**시도별 경계상자 16개**에서 시작한다(`seed_boxes`). 시군구 경계
(`data/geo/sgg_kr.geojson`)의 좌표를 시도로 묶어 만들고, 경계에 붙은 숙소가
빠지지 않게 0.05도 여유를 둔다.

처음에는 전국을 사각형 하나 `(32.95, 124.50) ~ (38.65, 131.90)` 로 덮었다.
그랬더니 **규슈가 통째로 들어왔다** — 1차 수집 41,856건 중 버린 3,972건의
가장 큰 덩어리가 후쿠오카(33.50N, 130.25E) 1,694건이었고, 벳푸·나가사키가
뒤를 이었다. 받는 만큼 예산이 사라지고 그 위를 쪼개느라 더 쓴다.

시도별로 자르면 덮는 면적이 421,378km² → 337,485km² 로 줄고, 일본 육지는
전부 빠진다. 시도끼리 조금 겹치지만 좌표는 키로 중복이 걸러진다.

북한은 육지 경계가 없어 애초에 들어오지 않는다.

```
pop bbox
  page1 = fetch(bbox)
  total = parse_total(page1)
  collect coords(page1)
  if total > SPLIT_AT and bbox 변이 MIN_DEG 보다 크면:
      push 4분할
  else:
      커서를 끝까지 밟아 좌표를 마저 모은다
```

- `SPLIT_AT = 180` — 실측 상한 약 200 보다 낮게 잡아 여유를 둔다.
- `MIN_DEG = 0.004` — 약 400m. 여기까지 쪼갰는데도 200건이 넘으면 더
  쪼개도 의미가 없다(명동·홍대). 그 leaf 는 `forced` 로 세어 두고 넘어간다.
  **이 경우 해당 격자의 숫자는 실제보다 작다. 화면에 그렇게 표시한다.**

한 bbox 를 끝까지 처리하지 못하고 예산이 떨어지면 그 bbox 를 frontier 에
되돌려 놓고 종료한다. 절반만 수집된 leaf 가 남지 않게 한다 — 완료로 쳐 버리면
그 지역 숙소가 이번 바퀴 내내 빠진 채로 남는다. 좌표는 키로 중복이 걸러지므로
다시 거둬도 손해가 없다.

**실패한 bbox 는 큐 앞으로 보낸다**(`requeue`). 스택은 끝에서 꺼내므로 끝에
되돌리면 같은 bbox 를 곧바로 다시 집는다 — 영구적으로 응답이 깨진 bbox 가
하나라도 있으면 그것만 다섯 번 두드리다 매 실행이 중단된다. 앞으로 보내면
나머지를 다 훑은 뒤에 다시 시도한다.

### 3.3 집계

화면 쪽은 기존 모듈을 그대로 쓴다 — `map.js`(시군구 클릭·툴팁·뷰 전환),
`palette.js`(색), `sorttable.js`(표 정렬), `freshness.js`(낡음 경고).
`map.js` 는 전국 시도 코드를 뷰 이름으로 받도록만 넓혔다(`prefixOf`).
새로 만든 건 `pointlayer.js`(캔버스 점)와 `airbnb-app.js` 둘뿐이다.

`build_airbnb.py` 가 만드는 것:

| 산출물 | 내용 |
|---|---|
| `assets/realestate/airbnb.json` | 시군구별 숙소 수·면적당 밀도, 시군구 경계상자, 전국 격자(0.005° ≈ 500m) 집계, 투영 파라미터, 수집 메타 |
| `assets/realestate/airbnb/<sgg>.json` | 시군구별 좌표 목록. 화면에서 그 지역을 볼 때만 받아간다 |

좌표→시군구 배정은 `data/geo/sgg_kr.geojson` 에 대한 point-in-polygon
(ray casting)으로 한다. 어느 시군구에도 안 들어가는 좌표(해상·국경 밖)는
버리고 개수를 로그에 남긴다.

시군구별 파일로 가르는 이유는 기존 `assets/realestate/sgg/<code>.json` 과
같은 이유다 — 전국 점을 한 파일에 담으면 모바일에서 첫 로딩이 무겁다.

## 4. 지도

현재 `_includes/realestate/map.svg` 는 시도 11·41(서울·경기)뿐이다. 전국이
필요하다.

- `build_geo.py` 에 `--sido`(기본 `11,41`), `--output`, `--projection`,
  `--max-bytes` 인자를 붙인다. 기존 기본 동작과 산출물은 그대로 둔다.
- 전국본 `_includes/realestate/map_kr.svg` + `data/geo/projection_kr.json`
  + `data/geo/sgg_kr.geojson.gz` 를 만든다. **경계 GeoJSON 은 gzip 으로 쓴다** —
  전국본이 날것으로 6.1MB 라 저장소에서 가장 큰 파일이 되는데(그 다음이 3.1MB),
  git 히스토리는 되돌릴 수 없다. 압축하면 1.6MB 다. `mtime=0` 으로 고정해
  내용이 같으면 바이트도 같게 만든다.
- 원본은 vuski/admdongkor 행정동 GeoJSON(약 34MB). 저장소에 넣지 않고
  결과물만 커밋한다 — 기존과 같은 방식이다.
- `build_geo.py` 의 시군구 대조는 `regions.sgg_codes()`(서울·경기 전용)를
  쓴다. 전국일 때는 이 대조를 건너뛰고 GeoJSON 의 `sgg`·`sido` 속성을
  그대로 신뢰한다.

**위험**: 서울·경기 72개 시군구가 eps 0.05 에서 225KB 다. 전국은 약 250개
시군구라 같은 강도로는 250KB 예산을 넘는다. 전국본은 eps 를 키워 따로 잡고,
실제 바이트를 재서 맞춘다. 넘으면 단순화 강도를 올린다 — 전국 뷰는 수도권
뷰만큼 확대되지 않으므로 거칠어도 된다.

## 4.1 확인한 것 (2026-09-22)

- 기본 빌드(서울·경기)는 인자화 뒤에도 **바이트까지 같은 `map.svg`** 를 낸다.
- 전국은 eps 0.5 에서 **229,469B / gzip 76,643B** — 사이트가 이미 쓰는
  `map.svg`(225,350B / 77,410B)와 같은 무게다. 시군구 256개가 모두 살아 있고
  제주·울릉도·옹진 섬들도 남았다.
- eps 0.35 는 299,643B(gzip 98,370B)로 예산을 넘는다. 전국 뷰는 1000px 폭에
  경도 7.4도를 담아 eps 0.5 가 화면에서 0.5px 이라 거칠어 보이지 않는다.

## 5. 화면

`_pages/dashboard-airbnb.md` → `/dashboard/airbnb/`.
`assets/realestate/airbnb-app.js`, `airbnb.css`.

- **전국 뷰**: 시군구 choropleth. 색은 `숙소 수 / 면적`(km² 당). 절대 수는
  서울이 다 먹으므로 밀도로 칠하고, 절대 수는 표에서 본다.
- **점 레이어**: SVG 위에 `<canvas>` 를 같은 투영으로 겹친다. 점이 수만 개라
  SVG 원으로는 못 그린다. 학군 지도(`schoolmap.js`)의 점 레이어는 38개 기준
  설계라 재사용하지 않는다.
- **탭**: 밀도 / 절대 수 / 점.
- **시군구 클릭**: 그 시군구의 좌표 파일을 받아 확대하고, 우측(모바일은
  아래) 패널에 순위·숫자를 띄운다.
- **표**: 시군구 순위표. 기존 `sorttable.js` 를 쓴다.
- **정직성 표시**: `forced` leaf 가 있는 격자는 "이 지역은 실제보다 적게
  잡힙니다" 로 표시한다. 수집 기준일도 함께 보여 준다.

모든 화면은 390px 에서 가로로 넘치지 않아야 한다. 표는 자체 스크롤
컨테이너 안에서만 넘긴다.

**시군구를 고르면 그 시도로 먼저 확대한다.** 전국 축척에서는 시군구 하나의
숙소가 몇 픽셀로 뭉개진다 — 실측으로 제주시 671곳이 캔버스 잉크 127px 이었고,
시도 확대를 넣으니 1,631px 이 됐다.

### 390px 검증은 `vw` 로 하지 않는다

`.re-app` 에 `overflow-x: hidden` 이 걸려 있어서, 앱 안에 900px 짜리 요소를
집어넣어도 `window.innerWidth` 는 390 그대로다. 판정은 **`.re-app` 안 모든
요소의 `getBoundingClientRect().right` 최댓값**으로 한다 — 같은 주입 실험에서
378 → 912 로 반응하는 것을 확인했다.

## 6. 크론

```
0 3 * * 0   airbnb_weekly.sh
```

일요일 새벽. `flock -w 7200 ~/.cache/realestate.lock` 을 반드시 붙인다 —
다른 수집기와 겹쳐 돌면 커밋이 유실된다. 로그는
`~/.cache/realestate-airbnb.log`.

첫 완주까지는 며칠 걸린다. 예산이 남은 frontier 를 다 비우면 그 실행은
바로 끝나고, 비우지 못하면 다음 주에 이어받는다. 한 바퀴를 다 돌면
frontier 를 전국 bbox 하나로 초기화해 다시 시작한다.

## 7. 테스트

```shell
python3 -m unittest discover -s tests
```

`airbnb_api.py` 만 테스트한다(순수 함수라 테스트가 붙는다).

- 고정 HTML 에서 좌표 20건·총건수·커서 15장을 뽑는가
- 총건수가 없는 HTML(차단·빈 결과)에서 0 을 돌려주는가 — 예외를 던지지 않는다
- bbox 4분할이 경계를 빠짐없이 덮고 겹치지 않는가
- bbox 밖 좌표를 걸러내는가
- 격자 스냅이 경계값에서 흔들리지 않는가

Airbnb 가 화면 구조를 바꾸면 파싱이 조용히 0건을 돌려줄 수 있다.
`collect_airbnb.py` 는 **첫 요청에서 좌표가 0건이면 즉시 실패시킨다** —
빈 결과로 기존 데이터를 덮어쓰지 않는다.

## 8. 단계

각 단계가 끝날 때 눈으로 확인할 것이 있다.

1. **수집기** — `airbnb_api.py` + 테스트 + `collect_airbnb.py`.
   확인: 제주 한 지역을 완주시켜 좌표 수와 호출 수를 본다.
2. **전국 지도** — `build_geo.py` 확장, `map_kr.svg` 생성.
   확인: SVG 바이트 예산, 시군구 개수, 브라우저에서 모양.
3. **집계** — `build_airbnb.py`.
   확인: 시군구 합이 전체 좌표 수와 맞는가, 버린 좌표가 몇 개인가.
4. **화면** — 페이지·JS·CSS.
   확인: 390px 오버플로, 지도 동작, 점 렌더 성능.
5. **크론** — `airbnb_weekly.sh`.

## 9. 안 하는 것

- 가격·평점·후기·호스트 정보 수집. 밀집도에 필요 없고 약관 위험만 키운다.
- 숙소 상세 페이지(`/rooms/...`) 접근. robots.txt 가 일부를 막고 있고,
  숙소 수만큼 요청이 늘어난다.
- 시계열. 첫 판은 스냅샷 하나다. 주간 스냅샷이 쌓이면 그때 붙인다.
- 체험(Experiences)·서비스. 숙소만 본다.
