# 시도별 아파트 착공 × 금리 대시보드 설계

작성일 2026-09-07 · 상태 **구현됨**(금리 수집만 `ECOS_API_KEY` 대기) · 경로 `/dashboard/supply/`

## 이 대시보드가 답하는 질문

두 가지다.

**공급 선행지표** — 지금 착공이 줄고 있으면 2~3년 뒤 입주가 마른다.
착공은 준공보다 2~3년 앞서므로, 오늘의 착공은 미래 입주물량의 예고편이다.

**도시 간 비교** — 어디가 먼저 얼어붙었나. 절대량으로는 서울 3,491호와
대구 21호가 같은 축에서 비교되지 않으므로 **각 시도의 평년 대비 지수**로 본다.

금리는 이 둘의 배경이다. 시행사가 삽을 뜨는 결정과 실수요자의 자금 조달이
금리에 걸려 있다. 다만 **이 대시보드는 상관을 보여줄 뿐 인과를 주장하지 않는다.**

## 하지 않는 것

- **시군구 단위.** 공개 통계에 없다. 아래 "지역 단위가 시도인 이유" 참조.
- **예측.** 착공에서 입주 시점을 역산해 주지 않는다. 시차는 사업마다 다르다.
- **상관계수·회귀.** 두 선을 나란히 놓기만 한다. 숫자로 인과를 암시하지 않는다.

## 지역 단위가 시도인 이유

설계 초기에는 기존 실거래·재개발 대시보드와 같은 서울·경기 시군구 72개를
목표로 했다. 국토교통 통계누리 API를 직접 호출해 확인한 결과, **주택 착공·준공·
인허가·분양 통계는 전부 시도 17개까지만 내려온다.**

| 통계 | formId | 지역 단위 |
|---|---|---|
| 주택유형별 착공실적(월계) | 5387 | 시도 |
| 주택건설 착공실적(월계) | 5386 | 시도 |
| 주택유형별 준공실적(월계) | 5373 | 시도 |
| 주택건설 인허가실적(월별 누계) | 1948 | 시도 |
| 주택건설 분양실적(공동주택) | 5557 | 시도 |
| 시도별 건축착공현황 | 2202 | 시도 |
| 시·군·구별 미분양현황 | 2082 | **시군구** |

시군구로 월별 제공되는 주택 통계는 미분양(2082) 하나뿐이다.

시군구 착공을 만들려면 건축HUB 주택인허가 대장(`DATA_GO_KR_API_KEY`)을 법정동
단위로 훑어 `stcnsDay`(착공일)와 `totHhldCnt`(총세대수)를 직접 집계하는 길뿐인데,
강남구 개포동 샘플 5건 중 착공일이 채워진 건 1건, 총세대수는 전부 0이었다.
법정동 수천 개를 훑어야 하고 공식 수치와 대조할 기준도 없다. **만들어도 믿을 수
없는 숫자가 나오므로 하지 않는다.**

시군구 미분양은 별도 2차 과제로 남긴다. 이 스펙의 범위가 아니다.

## 데이터 소스

전부 실제 호출로 검증했다.

| 계열 | 엔드포인트 | 인증 | 기간 |
|---|---|---|---|
| 아파트 착공 세대수 | `stat.molit.go.kr/portal/stat/data.do` `formId=5387` | 없음 | 2011-01 ~ |
| 한국은행 기준금리 | `ecos.bok.or.kr` `722Y001 / M / 0101000` | `ECOS_API_KEY` | 1999-05 ~ |
| 예금은행 주택담보대출 금리 | `ecos.bok.or.kr` `121Y006 / M / BECBLA0302` | `ECOS_API_KEY` | 2001-09 ~ |

착공 시작이 2011-01이므로 대시보드 전체 구간은 **2011-01 ~ 최신월**이다.

### 통계누리 요청 형태

```
GET /portal/stat/data.do?formId=5387&styleNum=1&apprYn=Y&startDate=YYYYMM&endDate=YYYYMM
```

응답은 컬럼 인덱스가 문자열 키인 평평한 배열이다.

```json
{"result": true,
 "data": [{"0": "2026-06 p)", "1": "서울", "2": "아파트",
           "3": "아파트", "4": "아파트", "5": "1605"}]}
```

컬럼 의미는 `/portal/stat/columns.do?formId=5387&styleNum=1` 이 준다.
`0`=월, `1`=지역, `2`=대분류, `3`=중분류, `4`=소분류, `5`=착공실적.

### ECOS 요청 형태

```
GET /api/StatisticSearch/{KEY}/json/kr/1/1000/{통계표}/M/{시작}/{종료}/{항목}
```

키가 없거나 한도를 넘으면 `{"RESULT": {"CODE": "ERROR-…", "MESSAGE": …}}` 로
**HTTP 200과 함께** 돌아온다. 상태코드만 보면 실패를 놓친다.

## 응답에 박힌 함정 다섯

이 다섯 개가 이 파이프라인의 실질적 난이도 전부다. 전부 실제 응답에서 확인했다.

### 1. 1회 조회 60개월 제한

61개월 이상을 요청하면 `{"result": false, "msg": "최대 5년(60개월)까지…"}` 가
**HTTP 200으로** 온다. `result` 를 안 보면 조용히 빈 데이터가 된다.
2011-01 ~ 현재는 5년 단위로 잘라 4회 호출한다.

### 2. 잠정치 표기 `p)`

최근 약 10개월이 `"2026-07 p)"` 형태로 온다. 확정되면서 **값이 바뀐다.**
월 문자열에서 `p)` 를 떼어 `provisional` 플래그로 분리하고, 화면에서 점선으로
구분한다. 수집기는 잠정월을 매 실행 재수집한다.

### 3. 집계행 혼입

지역 라벨 23종 중 5종이 합계행이다.

```
총계  수도권소계  지방소계  기타광역시  기타지방
```

거르지 않으면 이중계상된다. **화이트리스트 방식으로 실제 시도만 통과시킨다** —
블랙리스트로 짜면 나중에 합계행이 하나 추가될 때 조용히 섞인다.

### 4. 전남광주 통합 (2026-07-01)

전남광주통합특별시가 출범해 **2026-07부터 `광주`·`전남` 행이 사라지고 `전남광주`
한 행만 온다.** 15년 시계열 한가운데서 지역 축이 바뀐다.

처리: **전 기간에 걸쳐 광주와 전남을 합산해 `전남광주` 하나로 다룬다.**
2026-06 이전은 두 값을 더하고, 2026-07 이후는 통합값을 그대로 쓴다. 이렇게 하면
평년 기준선의 분모가 시계열 내내 일관된다. 시도는 17개가 아니라 **16개**가 된다.

둘 중 하나만 값이 있는 달은 합산하지 않고 결측으로 둔다. 반쪽만 더한 값은
통합 이전 구간을 조용히 과소계상한다.

### 5. `'-'` 결측 표기

세종은 **2011-01부터 행이 존재하지만 값이 `'-'`** 다. 실제 착공은 2012-10부터
잡힌다. `'-'` 를 0으로 읽으면 세종의 평년 기준선이 바닥으로 깔려 지수가 폭주한다.

`'-'`·빈 문자열·숫자로 파싱되지 않는 값은 전부 **결측(None)** 이다. 0이 아니다.
0은 "그 달에 착공이 없었다"는 실제 관측값이고 결측은 "모른다"다. 둘을 섞지 않는다.

## 파이프라인

저장소 규칙(`CLAUDE.md`)을 그대로 따른다. **표준 라이브러리만 쓴다.**

| 파일 | 층 | 역할 |
|---|---|---|
| `scripts/molit_stat_api.py` | 순수함수 | 통계누리 응답 파싱. I/O 없음 |
| `scripts/ecos_api.py` | 순수함수 | ECOS 응답 파싱. I/O 없음 |
| `scripts/collect_supply.py` | I/O | 두 소스 호출, 원본 보존 |
| `scripts/build_supply.py` | 집계 | `assets/realestate/supply.json` 생성 |
| `scripts/supply_monthly.sh` | 크론 | 진입점 |

### `molit_stat_api.py` (순수함수)

```
SIDO = {"서울", "인천", "경기", "부산", "대구", "광주", "대전", "울산", "세종",
        "강원", "충북", "충남", "전북", "전남", "경북", "경남", "제주",
        "전남광주"}                # 화이트리스트. 여기 없는 라벨은 전부 버린다
parse_starts(payload) -> tuple[list[Row], dict[str, int], str | None]
```

`전남광주` 를 화이트리스트에 함께 둔다. 2026-07부터 오는 통합 라벨이며,
`광주`·`전남` 과 같은 달에 동시에 오지는 않는다.

`Row` 는 `{month, region, units, provisional}` 이다. 반환값은 세 개다.

    rows    시도 행 목록
    totals  월 -> 전국 총계 아파트 착공. build 단계의 대조용으로 실어 나른다
    error   오류 사유. 정상이면 None

`result: false` 와 예상 밖 구조를 여기서 잡는다.

- 월: `"2026-07 p)"` → `("2026-07", True)`, `"2025-09"` → `("2025-09", False)`
- 대분류(`"2"`)가 `아파트` 인 행만
- 지역이 화이트리스트에 없으면 버림
- 값: `'-'`·빈값·비숫자 → `None`. 음수 → `None`
- 광주·전남 합산은 여기서 하지 않는다. 원본 충실성을 유지하고 `build` 에서 합친다

**정상성 게이트** (`collect_fx.py` 의 `SANE` 패턴):
한 달 전국 아파트 착공 합계가 `0` 이거나 `200000` 초과면 응답이 이상한 것으로
보고 그 달을 통째로 버린다. 부분적으로 틀린 시계열이 조용히 섞이는 게 더 위험하다.

### `ecos_api.py` (순수함수)

```
parse_series(payload) -> tuple[list[tuple[str, float]], str | None]
```

- `RESULT.CODE` 가 있으면 오류 사유를 반환
- `TIME` `"202601"` → `"2026-01"`
- `DATA_VALUE` 를 float 로. 실패 시 그 점만 버림
- 금리 정상 범위 `0.0 ~ 30.0` 밖은 버림

### `collect_supply.py` (I/O)

```shell
python3 scripts/collect_supply.py [--from 201101] [--force]
```

- 통계누리: 2011-01부터 현재까지 60개월 청크로 분할 호출
- **확정월은 재수집하지 않는다. 잠정월은 매 실행 재수집한다.** 이게 이 수집기의
  핵심이다 — 잠정치는 값이 바뀌는데 캐시가 잡아먹으면 영원히 옛 값을 쓴다
- ECOS: 2011-01 ~ 현재를 한 번에 (1000건 한도 안에 들어온다)
- `ECOS_API_KEY` 가 없으면 **명확히 실패**하고 종료코드 1. `sample` 키로 조용히
  대체하지 않는다 — 10건 제한이라 반쪽 시계열이 만들어진다
- 실패 시 기존 파일을 그대로 둔다. 지난달 데이터가 빈 파일보다 낫다
- 산출: `data/supply/starts.json`, `data/supply/rates.json`

### `build_supply.py` (집계)

1. `starts.json` 로드 → 광주 + 전남 → `전남광주` 합산
2. **전국 계열 생성** — 16개 시도의 합으로 직접 계산한다. 응답의 `총계` 행을
   쓰지 않는 이유는 아래 "전국은 왜 직접 더하는가" 참조
3. 시도별 월 착공 원계열 `units[]`
4. **12개월 이동합계** `mavg[]` — 창 안에 결측이 하나라도 있으면 그 지점은 결측.
   창이 12개월이므로 `mavg` 는 **2011-12부터** 정의된다. 앞 11개월은 `null`
5. **평년 지수** `index[]` — 각 시도의 **2011-12 ~ 2019-12** `mavg` 평균을 100
6. 금리 2계열을 월 축에 정렬

#### 전국은 왜 직접 더하는가

응답에는 `총계` 합계행이 있지만 쓰지 않는다. 16개 시도를 직접 더해 만들고,
**`총계` 행과 대조해 검증에만 쓴다.** 차이가 1% 를 넘으면 화이트리스트에서
시도가 빠졌거나 라벨이 바뀐 것이므로 빌드를 실패시킨다.

전남광주 통합 같은 사건이 또 일어나면 새 라벨이 화이트리스트에 없어 조용히
누락되는데, 개수를 세는 검사로는 이걸 못 잡는다 — 지역 수가 줄어도 나머지는
멀쩡하기 때문이다. 합계 대조가 이걸 잡는 유일한 장치다.

산출 `assets/realestate/supply.json`:

```json
{"generated": "2026-09-07",
 "latest_month": "2026-07",
 "provisional_from": "2025-10",
 "baseline": {"from": "2011-12", "to": "2019-12", "min_months": 60},
 "months": ["2011-01", "…"],
 "regions": [{"code": "00", "name": "전국", "units": [], "mavg": [], "index": []},
             {"code": "11", "name": "서울", "units": [], "mavg": [], "index": []}],
 "rates": {"base": [], "mortgage": []},
 "notes": ["광주·전남은 2026-07 통합에 따라 전 기간 합산"]}
```

`regions[0]` 은 항상 전국(`code: "00"`)이며 16개 시도가 뒤따른다. 즉 배열 길이는
**17**이다. 화면은 전국을 배경 기준선으로, 나머지를 선택 대상으로 쓴다.

크기는 17계열 × 187개월 × 3배열 ≈ 9천 숫자로 100KB 안쪽이다. gzip 하지 않는다.
(gzip 을 쓰게 되면 저장소 규칙대로 `mtime=0` 을 고정할 것.)

#### 왜 12개월 이동합계인가

착공은 단발 대규모 사업 하나에 월값이 통째로 흔들린다. 서울만 봐도
2025-01 1,605호에서 2026-06 3,491호로 튄다. 원계열은 톱니라 추세가 안 보인다.
12개월 이동합계는 계절성을 정의상 제거하고, 단위가 "최근 1년간 착공 호수"라
직관적이다. 이동평균이 아니라 합계를 쓰는 이유도 그 직관 때문이다.

#### 왜 기준선이 2011~2019인가

2020 이후는 코로나와 금리 급등이 겹친 예외 구간이다. 기준선에 넣으면 기준 자체가
왜곡돼 "평년 대비"라는 말이 무의미해진다. 2011~2019는 9년으로 충분히 길고
정책 사이클이 한 바퀴 이상 돈다.

기준 구간의 `mavg` 는 최대 **97개월**(2011-12 ~ 2019-12)이다. 세종처럼 결측이
많은 시도는 **값이 있는 달만으로 평균**하되, 유효 개월이 **60 미만이면 `index` 를
전부 `null`** 로 두고 화면에서 "지수 없음"으로 표시한다. 짧은 기준선으로 만든
지수는 숫자만 그럴듯하고 뜻이 없다.

세종은 착공이 2012-10부터 잡히므로 `mavg` 가 2013-09부터 정의되고, 기준 구간의
유효 개월이 약 76개월이라 이 문턱을 통과한다. 문턱은 세종을 떨어뜨리려고 두는
게 아니라, 앞으로 새로 생기거나 통합되는 광역단체를 막으려고 둔다.

### 왜 이중축이 아니라 2단 패널인가

이중 Y축은 **두 축의 눈금을 어떻게 잡느냐로 상관관계를 있어 보이게도 없어
보이게도 만들 수 있다.** 눈금을 고르는 순간 만든 사람이 결론을 정하는 셈이다.

x축을 공유하는 상하 2단 패널은 시점 대응을 그대로 읽히게 하면서 그 조작 여지가
없다. 착공 라인이 금리 라인에 눌려 납작해지지도 않는다. 390px 에서도 세로로
쌓이는 구조라 안전하다.

### 차트 구현

`assets/realestate/charts.js` 에 `multiLinePanel()` 을 추가한다. 기존 `lineChart`
는 단일 계열이고 축 단위가 `만원/평` 으로 박혀 있어 재사용할 수 없다. `niceTicks`
는 공유한다.

색은 `palette.js` 의 `CATEGORICAL` 4색을 그대로 쓴다. **지역 선택을 4개로 제한하는
이유가 이것이다** — 5개째부터는 색 대비 검증이 깨진다. 전국은 `MUTED` 회색 얇은
선으로 항상 배경에 깔아 기준선 역할을 시킨다(선택 4개에 포함하지 않는다).

잠정 구간은 기존 `lineChart` 의 `partialFrom` 과 같은 방식으로 점선 처리한다.

## 구현하며 설계가 틀린 것으로 드러난 것

전부 **`총계` 합계 대조가 잡아냈다.** 이 스펙에서 가장 값을 한 장치다 — 없었으면
셋 다 조용히 틀린 숫자로 굳었다.

### 1. 음수는 결측이 아니다

스펙은 "값: `'-'`·빈값·비숫자 → `None`. 음수 → `None`" 이라고 적었다. 틀렸다.

통계누리는 **하향 정정을 음수 월값으로 준다.** 2011-12 충남이 `-1494` 다
(2013-12·2025-07·2025-08 도 마찬가지). 음수를 버리자 그 네 달의 시도 합이
`총계` 를 넘어 빌드가 멈췄고, 원본을 다시 부르니 실제로 음수였다.

음수는 12개월 이동합계 안에서 앞달의 과대계상을 상쇄하므로 그대로 들고 간다.
버리면 이동합계가 그만큼 부풀고, `총계` 와도 어긋난다.

### 2. `'-'` 의 대부분은 0 이다

스펙은 `'-'` 를 전부 결측으로 뒀다. 그대로 두니 **시도 16곳 중 7곳이 지수를
통째로 잃었다.** 결측 하나가 12개월 창을 12번 죽이는데, 대전(기준구간 10개월
결측)·충북(9)·전북(9)처럼 `'-'` 가 흩뿌려진 시도는 유효 개월이 60 문턱을
못 넘긴다.

`'-'` 에는 두 가지가 섞여 있다 — "그 달 착공이 0" 과 "그때 그 시도가 아직 없었다".
응답만 봐서는 구분이 안 된다. 구분하는 근거는 다시 **합계 대조**다. `'-'` 를 빼고
더한 시도 합이 187개월 **전부** `총계` 와 맞으므로, 관측 구간 안의 `'-'` 는 실제로
0 이다. 관측 시작 이전(세종의 2011~2012)만 결측으로 남긴다.

`build_supply.fill_observed_gaps()` 가 이걸 한다. 응답이 아예 안 내려준 달은
채우지 않는다 — 0 을 그려 넣으면 없던 관측을 만들어 내는 셈이다.

결과: 16개 시도 전부 지수를 얻는다. 세종만 `mavg` 가 2013-07 부터다.

### 3. 세종의 첫 착공은 2012-10 이 아니라 2012-08 이다

스펙이 "세종은 2012-10부터"라고 적었는데 실제 데이터는 2012-08 이다.
`mavg` 는 그 12개월 뒤인 2013-07 부터 정의된다. 기준구간 유효 개월은 78 로
문턱(60)을 통과한다. 화면 하단 한계 표기는 스펙 문구를 그대로 뒀다 — 한 달
차이라 독자에게 주는 뜻이 같고, 정확히는 "2012년 하반기"다.
