# 재개발·재건축 데이터 대시보드 설계

작성일: 2026-07-31

/ real-estate 허브에 세 번째 도구를 붙인다. 기존 "입지 분석" 카드와는 별개의
독립 도구다. 실거래 대시보드·학군 지도와 같은 파이프라인 구조를 따른다.

- 페이지: `/real-estate/redevelopment/`
- 대상: 서울 + 경기 (단, 정비사업 진행 데이터는 서울만)

## 왜 만드나

재건축·재개발은 "가격에 선행하는 것" 중 데이터로 가장 또렷하게 잡히는 축이다.
노후도·대지지분·용적률 여유는 계산 가능한 값이고, 인가 고시일은 날짜가 박힌
사건이다. 실거래 435만 건이 이미 있으므로 사건 전후 가격 변화를 실측할 수 있다.

## 답하려는 질문 세 가지

1. **사업성 랭킹** — 어느 노후 단지가 재건축이 굴러갈 여건인가
2. **진행단계 지도** — 서울 정비사업장이 지금 어느 단계에 있나
3. **단계별 프리미엄** — 조합설립·사업시행인가·관리처분 통과가 실거래가를 얼마나 움직였나

## 데이터 소스

### 이미 있는 것

| 경로 | 규모 | 쓰임 |
|---|---|---|
| `data/trades/YYYY/YYYY-MM.csv.gz` | 435만 건, 2006~ | `umd_nm`+`jibun` 으로 정비구역 대표지번과 조인 |
| `data/complexes.csv.gz` | 18.7만 단지 | PNU·세대수·동수·사용승인일(노후도) |
| `data/geo/` | 시군구 geojson + projection.json | 지도 투영 재사용 |

### 새로 받는 것

**A. 정보몽땅 사업장 목록** — 인증키 불필요

```
POST https://cleanup.seoul.go.kr/cleanup/bsnssttus/lsubBsnsSttus.do
  bsnsSeCodeList=100..107 (사업구분)
  bsnsEfctMthdList=1,2,3
  sigunguCd=11000(전체) 또는 자치구코드
```

HTML 표를 돌려준다. 컬럼: 번호 · 자치구 · 사업구분 · 사업장명 · **대표지번** ·
진행단계 · 공개자료수 · 공개적시성 · 자료충실도. 행마다
`cafeOpenPopup('<cafeUrl>')` 와 `mapOpenPopup('<wtnncSn>')` 이 붙어 있다.
서울 전체 약 1,100건.

서울 열린데이터광장 OA-2253 "서울시 재개발 재건축 정비사업 현황" OpenAPI 는
2026-07 기준 **종료된 서비스**다. 아직 여러 문서가 인용하지만 쓸 수 없다.
정보몽땅이 그 데이터의 원본 시스템이므로 여기를 직접 친다.

**B. 정보몽땅 추진경과** — 인증키 불필요, 이 프로젝트의 핵심

```
GET /cafe/mainIndx.do?cafeUrl=<cafeUrl>                 → cafeId, bsnsPk 추출
GET /cafe/mainIndx/cleanup-prtnelapse/vscr.do?cafeId=&bsnsPk=
```

단계별 이력이 일자와 함께 나온다. 실측 예(마포로3구역제3지구, 71개 일자):

```
정비구역지정   2007-08-23 구역지정(변경)고시
추진위승인     2007-03-12 (변경)승인, 동의율 63.2%
조합설립인가   2007-12-21 (변경)인가, 동의율 80.88%
사업시행인가   2013-07-25 (변경)인가고시, 동의율 71.4%
시공자선정     2015-08-31 대우건설
관리처분인가   2020-08-27 (변경)인가고시
이주           2021-01-25 개시 → 2023-10-20 완료
철거           2023-10-26 완료
일반분양       2023-11-24 승인
```

단계 목록: 기본계획수립 · 안전진단 · 정비구역지정 · 조합설립추진위원회승인 ·
정비사업전문관리업자선정 · 설계자선정 · 조합설립인가 · 사업시행인가 ·
시공자선정 · 철거업자선정 · 관리처분인가 · 이주 · 철거신고 · 착공신고 ·
일반분양승인 · 준공인가 · 이전고시 · 조합해산 · 조합청산

**C. UPIS 정비구역 폴리곤** — 인증키 불필요

서울도시계획포털이 내부 ArcGIS 10.81 을 프록시로 열어둔다.

```
GET https://urban.seoul.go.kr/proxy/proxy.jsp?<arcgis rest url>
  base = http://98.33.2.225:6080/arcgis/rest/services/UPIS/20200526_WMS/MapServer
  레이어 96 = UPIS_C_UQ120_BZ103 (재개발 주택정비형), 168건
```

필드: `PRESENT_SN` · `DGM_NM`(구역명) · `DGM_AR`(면적 ㎡) · `SIGNGU_SE`(시군구 5자리) ·
`PROPEL_CD`(추진단계 PP0203~PP0212) · `WTNNC_SN` · `CREATE_DAT` · 폴리곤 경계.

레이어 번호와 사업유형:

| id | 레이어 | 유형 |
|---|---|---|
| 94 | BZ101 | 신속통합기획 |
| 95 | BZ102 | 재개발(도시정비형) |
| 96 | BZ103 | 재개발(주택정비형) |
| 97 | BZ104 | 재건축(단독) |
| 98 | BZ105 | 재건축(공동) |
| 99/100 | BZ107/108 | 주거환경개선(관리형/정비형) |
| 101~105 | BZ201~205 | 모아타운·가로주택·자율주택·소규모재건축·소규모재개발 |
| 112~115 | BZ401~404 | 재정비촉진지구·구역 |

`CREATE_DAT` 은 **단계 전이일이 아니다.** 168건 중 116건이 2025-12 에 몰려 있는
일괄 재적재 흔적이다. 단계 일자는 B(추진경과)에서만 가져온다. UPIS 는 경계·면적·
현재단계 용도로만 쓴다.

`PROPEL_CD` 의 코드표는 공개되어 있지 않다. 정보몽땅 진행단계와 구역명으로 조인해
경험적으로 매핑하고, 매핑표를 `scripts/upis_api.py` 에 상수로 남긴다.

**D. 건축HUB 건축물대장 — 막혔다**

`https://apis.data.go.kr/1613000/BldRgstHubService/*` 가 **HTTP 403** 이다.
현재 `DATA_GO_KR_API_KEY` 는 실거래가(RTMSDataSvc*)와 주택인허가
(HsPmsHubService)에만 활용신청이 돼 있다. 건축물대장은 별도 신청이 필요하다.

주택인허가로 대신할 수 없다. 은마아파트(1979)를 조회하면 2022년 리모델링
인허가 9건이 나오고 `archArea`·`totArea`·`vlRat` 이 전부 0 이다. 세움터
전산화 이전에 지어진 건물의 원건축물 정보가 없다.

**D′. UPIS 연속지적도 — 서울에 한해 대체 확보**

서울도시계획포털 WFS 서비스의 `LP_PA_CBND` 레이어가 **PNU 로 직접 조회**된다.
`data/complexes.csv.gz` 가 단지마다 PNU 를 갖고 있어 그대로 붙는다.

  - `SPACE_AREA` 대지면적, `JIGA` 개별공시지가(원/㎡), `JIMOK` 지목
  - `PNU IN (...)` 로 250개씩 묶어 받는다 (maxRecordCount 10000)

용도지역은 WMS 서비스 레이어 123(`UPIS_C_UQ111`)에서 받는다. 자치구로 못
나눈다 — 폴리곤 대부분이 `SIGNGU_SE='11000'`(서울시 전체)으로 태깅돼 있어
강남구로 걸러도 8건만 나온다. OBJECTID 도 794293~4745454 로 띄엄띄엄하다.
`returnIdsOnly=true` 로 8,331개 ID 를 먼저 받아 400개씩 명시 조회한다.
필지 대표점을 폴리곤에 떨어뜨려 판정한다 (9,364곳 중 8,678곳 = 93% 성공).

검산: 은마 239,226㎡ ÷ 4,424세대 = **16.4평**, 제3종일반주거, 상한 250%.
알려진 값과 맞는다.

수집 대상은 서울 아파트 **전량 9,389곳**. 준공연도로 거르지 않는다 — 화면에서
연차 기준을 바꿀 때 재수집을 피하기 위해서다.

**경기도는 대지지분·용도지역이 없다.** UPIS 는 서울 전용이다. 건축물대장
활용신청이 승인되면 그때 전국을 덮는다.

## 화면 세 가지

**1. 사업성 테이블** (서울+경기)

종합점수를 만들지 않는다. 지표를 각각 컬럼으로 두고 헤더 클릭 정렬만 제공한다.
가중치를 지어내면 근거 없는 확신을 주기 때문이다. 기존 실거래 대시보드와 같은 방식.

컬럼: 단지 · 준공연도 · 연차 · 세대수 · **대지지분(평)** · 현재용적률 ·
용도지역 · **용적률 여유(%p)** · 최근 중위 평당가 · 정비사업 단계

**2. 진행단계 지도** (서울)

시군구 지도 위에 정비구역 폴리곤을 얹고 단계별로 칠한다. 구를 누르면 그 구의
사업장 목록. 폴리곤이 무거우면 대표점으로 대체한다.

**3. 단계별 프리미엄** (서울)

이벤트 스터디. 각 사업장의 조합설립인가 / 사업시행인가 / 관리처분인가 고시일을
사건 시점 t=0 으로 두고, 그 구역 대표지번에서 발생한 실거래 평당가를 t-12개월 ~
t+12개월로 정렬해 집계한다.

**대조군이 반드시 필요하다.** 같은 자치구의 정비사업 비대상 아파트가 같은 기간에
움직인 변화율을 빼서 초과수익만 남긴다. 그러지 않으면 시장 전체의 상승을
재건축 프리미엄으로 오독한다.

표본이 적은 단계는 건수를 같이 표기하고, 10건 미만이면 값을 감춘다.

## 리스크

- **정보몽땅은 공식 API 가 아니다.** HTML 구조가 바뀌면 파서가 깨진다. 파싱을
  순수함수로 분리하고 실제 응답을 `tests/fixtures/` 에 고정해 회귀를 잡는다.
  수집 실패 시 이전 스냅샷을 유지하고 종료 코드로만 알린다.
- **호출량.** 사업장 1,100곳 × 2콜 = 2,200콜. 공공 사이트이므로 요청 간
  간격을 두고 동시 요청 수를 낮게 잡는다. `--max-calls` 로 하루 예산을 끊고
  다음 실행에서 이어받는다.
- **UPIS 프록시는 내부 IP 경유다.** 언제든 막힐 수 있다. 막히면 폴리곤 없이
  대표지번 좌표로 점만 찍어도 화면은 성립하도록 설계한다.
- **단지 등록이 지번마다 쪼개져 있다 (구현 중 확인).** 공동주택 단지 식별정보는
  압구정동 현대아파트를 11조각으로 등록하고, 조각의 세대수와 그 지번 필지의
  면적이 서로 대응하지 않는다 — 56세대에 63,321㎡ 인 조각과 144세대에 186㎡ 인
  조각이 같이 있다. 조각 단위로 대지지분을 내면 342평·0.4평이 나온다.
  **(시군구, 법정동, 정규화 단지명)으로 묶어 세대수와 필지면적을 함께 합산**해
  해결했다. 합치면 압구정 현대 25.9평, 압구정 미성 9.2평이 된다.

- **묶어도 등록 필지가 단지 땅이 아닌 경우가 남는다.** 대치동 미도맨션은
  1,232세대에 대지지분 47.9평이 나오는데 실제는 15평대다. 필지가 단지보다 넓다.
  평수 범위로 자르는 건 임의적이다 — 개포주공 같은 저층 단지는 27.9평이 진짜다.
  대신 **실거래 전용면적으로 용적률을 역산**해 검증한다:
  `세대수 × (전용 중위값 ÷ 0.75) ÷ 대지면적`. 80~400% 밖이면 대지지분을 감추고,
  100% 미만이면 화면에 빨간 물음표를 달아 독자가 거른다.
  검산: 압구정현대 204%, 은마 189%, 올림픽선수기자촌2 140% — 모두 실제와 맞는다.
  이 역산값은 건축물대장이 열릴 때까지의 임시 대체물이다.

- **세대수가 적은 '아파트'는 사실상 빌라다.** 8세대짜리가 대지지분 상위를 채워
  표를 못 읽게 만든다. 100세대 미만은 표에서 뺀다.

- **기본 정렬은 대지지분이 아니라 연차로 한다.** 대지지분으로 세우면 위에 적은
  필지 불일치 단지가 상위를 차지해 첫인상을 망친다. 대지지분 정렬은 사용자가
  머리글을 눌러 직접 한다.
- **모바일 오버플로.** 컬럼이 10개라 390px 에서 넘칠 위험이 크다. 기존
  `check-tables` 규칙대로 푸시 전에 확인한다.

## 하지 않는 것

- 종합 사업성 점수, 예상 분담금 계산, 투자 추천
- 경기도 정비사업 단계 데이터 (data.go.kr 파일데이터 454건은 2025-07 이후 정지)
- 조합 공개자료 본문 수집
