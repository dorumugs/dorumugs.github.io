# 부동산 실거래가 대시보드 — 시각화 설계

작성일: 2026-07-26
상태: 승인됨
선행 문서: `2026-07-25-real-estate-dashboard-design.md` (수집 파이프라인)

## 배경

수집은 끝났다. 2026-07-26 기준 (시군구 × 월) 격자 **17,784칸 전부 완료, 실패 0**.
2006-01 ~ 2026-07 247개월, 서울·경기 72개 시군구, 거래 **4,352,431건**, 52MB.
단지 마스터 `data/complexes.csv.gz` 도 완료(187,208건, 300세대 이상 5,139개 단지).

선행 문서가 "백필 완료 후 별도 진행"으로 미뤄둔 시각화가 이 문서의 범위다.

## 목표

`/real-estate/` 에 서울·경기 아파트 실거래 대시보드를 띄우고, 같은 이름의 블로그
카테고리를 만들어 지표를 하나씩 늘려가며 글로 기록한다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 화면 구성 | 지도 + 지표 + 단지 표를 한 화면에 |
| 기준 가격 지표 | **평당가 중위값** (3.3058㎡당) |
| 지역 입도 | 시군구 단위 그대로 72개 (수원시 4구를 합치지 않음) |
| 세대수 필터 | 기본 300세대+, 전체로 토글 |
| 구현 방식 | 바닐라 JS + SVG, 외부 라이브러리 없음 |
| 지도 배치 | 서울 / 경기 / 전체 **탭 전환** |
| 레이아웃 | 좌 지도 / 우 지표·차트 **2단**, 하단 전체폭 단지 표 |
| 다크모드 | 없음 (사이트 스킨이 `default` 라이트 전용) |

## 아키텍처

```
data/trades/*.csv.gz  (435만 건, 불변)   ─┐
data/complexes.csv.gz (세대수)           ─┤  scripts/build_dashboard.py
data/geo/sgg.geojson  (경계, 1회 생성)    ─┘        │
                                                   ▼
              assets/realestate/summary.json         구×월 집계
              assets/realestate/sgg/{code}.json ×72   단지×월 집계 (lazy load)
              _includes/realestate-map.svg           빌드타임 SVG path
                                                   │
                                                   ▼
                              _pages/real-estate.md  →  /real-estate/
```

원본 → 집계 → 표현의 3단 분리는 선행 문서의 원칙을 그대로 잇는다. 지표 정의가
바뀌면 집계만 다시 돌린다. 재수집은 없다.

## 경계 데이터

출처: `vuski/admdongkor` **ver20260701** (`HangJeongDong_ver20260701.geojson`, 34MB).

서울·경기 행정동 3,558개를 `properties.sgg` (시군구 5자리)로 병합하면
**정확히 72개**가 나오고, `scripts/regions.py` 의 72개 코드와 **완전히 일치**한다.
2025년 신설된 화성시 만세구·효행구·병점구·동탄구, 2024년 부활한 부천시 3개 구가
모두 들어 있다. (2013년판 `southkorea-maps` 는 이 구들이 없어 사용할 수 없다.)

### 저장소에 커밋한다

원본 34MB를 매 빌드마다 받지 않는다. 시군구 병합 + 좌표 단순화 결과를
`data/geo/sgg_seoul_gyeonggi.geojson` 로 커밋한다.

단순화는 Douglas-Peucker. 실측:

| eps | 결과 SVG | 비고 |
|---|---|---|
| 0.6 | 254KB | 과함 |
| 1.5 | 152KB | |
| **2.5** | **110KB** | 채택. 72개 전부 유지, gzip 후 약 30KB |

`minarea` 15 미만 폴리곤(먼 섬·자투리)은 버린다. 단순화 후 **72개 중 빈 path가
하나도 없어야** 하며, 하나라도 비면 빌드를 실패시킨다.

### 투영

등장방형(equirectangular) + 위도 보정 `k = cos(lat_mid)`. 별도 라이브러리가 필요
없고 이 정도 면적에서는 왜곡이 눈에 띄지 않는다.

투영 결과 종횡비:

- 서울·경기 전체: 1 : 1.20 (세로로 김 — 전체폭 배치가 불가능한 이유)
- 서울만: 1 : 0.82

탭 전환을 고른 근거가 이 숫자다. 통합 지도를 본문 폭 900px에 꽉 채우면 세로가
1,080px를 넘고, 서울 25개 구가 가운데 작게 뭉쳐 모바일에서 누를 수 없다.

## scripts/build_dashboard.py

### 입력 처리

1. `data/trades/*/*.csv.gz` 247개를 순회
2. `cdeal_type == 'O'` (계약해제) 는 **가격 집계에서 제외**하되 해제율 계산에는 쓴다
3. `area_sqm <= 0` 인 행은 버린다
4. 평당가 = `price_10k / (area_sqm / 3.3058)` — 단위 만원/평
5. PNU 조립 후 단지 마스터와 조인 (선행 문서의 2단 조인 그대로: PNU 완전일치 →
   시군구+법정동+정규화 단지명 → 미매칭은 세대수 미상)
6. 세대수 미상은 `300+` 집계에서 빠지고 `전체` 집계에는 들어간다

### 출력 1 — `assets/realestate/summary.json`

구 × 월 집계. 72 × 247 × 2(필터) = 35,568 레코드.

```
{
  "months": ["2006-01", ..., "2026-07"],
  "sgg": {"11680": {"name": "강남구", "sido": "11"}, ...},
  "series": {
    "300": {"11680": {"med": [2599, ...], "n": [243, ...], "cancel": [0, ...]}},
    "all": {...}
  }
}
```

배열 인덱스가 `months` 와 대응한다. 키 반복을 없애 크기를 줄인다.
거래가 없는 달은 `null`. 목표 크기 200KB 이하(gzip 후 40KB 내외).

`cancel`(계약해제 건수)은 1차에서 화면에 쓰지 않지만 집계에는 **미리 담는다.**
2차에서 해제율 지표를 켤 때 집계를 다시 돌리지 않아도 되고, 247개월 재집계
비용에 비해 배열 하나를 더 얹는 비용이 훨씬 싸다.

### 출력 2 — `assets/realestate/sgg/{code}.json`

구별 단지 × 월 집계. 구를 처음 누를 때 받는다.

(단지 × 면적구간 × 월) 조합은 전체 202만 개, 구당 중앙값 25,985개,
최대 72,953개(시흥시). 문자열 반복을 없앤 컬럼 배열 포맷으로 구당 100~300KB를
목표로 한다. 300KB를 넘는 구가 나오면 **오래된 연도를 연 단위로 접는다**
(최근 5년은 월 단위, 그 이전은 연 단위).

### 출력 3 — `_includes/realestate/map.svg`

72개 `<path id="sgg-{code}" data-name="...">` 만 담은 SVG **한 장**. 색은 넣지
않는다 — 런타임에 JS가 `fill` 을 칠한다.

서울/경기/전체 탭은 **같은 SVG의 `viewBox` 를 바꿔** 구현한다. 지도를 3벌
만들지 않으므로 파일이 하나로 끝나고, 탭 전환에 부드러운 전환도 붙일 수 있다.

대신 단순화 강도를 **가장 확대되는 뷰(서울)** 기준으로 잡아야 한다. 통합 투영에서
서울로 좁히면 약 2.6배 확대되므로, 전체 뷰에서 적당해 보이는 eps 2.5는 서울에서
각져 보인다. eps 1.0 근처에서 시작해 서울 뷰를 눈으로 확인하며 정하고,
**원본 250KB(gzip 후 60KB) 예산**을 넘기지 않는다.

`_includes/` 는 테마 원본 디렉터리라 저장소 규칙상 손대지 않는 곳이다. 기존 파일은
전혀 건드리지 않고 `_includes/realestate/` 하위 디렉터리를 새로 만들어 그 안에만
넣는다. Jekyll `{% include %}` 로 인라인해야 요청 한 번을 아끼고 CSS가 곧바로
path를 잡을 수 있다.

### 결정론적 출력

JSON 키를 정렬하고 부동소수 자리수를 고정한다. 데이터가 바뀌지 않은 구는 파일
바이트가 같아 git이 아무것도 기록하지 않는다. 원본 gzip에 적용한 원칙과 같다.

## 지표

지도 채색 지표 5종. 셀렉트로 전환한다.

| 지표 | 정의 | 색 유형 |
|---|---|---|
| 중위 평당가 | 기준월 중위 평당가 | 순차 (파랑 농도) |
| 변화율 3/6/12개월 | 기준월 대비 n개월 전 중위 평당가 변화율 | 발산 |
| 전고점 대비 | 기준월 ÷ 역대 최고월 − 1 | 발산 |
| 거래 회전율 | 최근 12개월 거래 수 ÷ 대상 단지 총 세대수 | 순차 |
| 계약해제율 | 해제 건수 ÷ 전체 신고 건수 (**2차로 미룸**) | 순차 |

### 표본이 얇은 달

월 거래가 5건 미만인 (구, 월) 은 중위값을 내되 **얇음 표시**를 달고, 변화율
계산에는 3개월 이동중위를 쓴다. 경기 외곽 군 지역에서 한두 건이 전체를 흔드는
것을 막는다.

### 기준월의 함정

가장 최근 달은 신고 지연 때문에 항상 미완성이다 (2026-07은 수집 시점에 64건,
직전 달 2026-06은 200건). 기본 기준월을 **직전 완료 월**로 두고, 최근 달은
"집계 중"으로 표시한다.

구 이름과 값을 툴팁으로 띄운다. 표 보기로도 같은 값을 확인할 수 있다.

## 화면

```
[ 서울 | 경기 | 전체 ]      [지표 ▾] [기준월 ▾] [300세대+]
┌─────────────────┬──────────────────┐
│                 │  <구 이름>        │
│      지도        │  KPI 3장          │
│    (탭 전환)     │  평당가 추이 차트  │
└─────────────────┴──────────────────┘
           단지 랭킹 표 (전체 폭)
```

- 구 선택 전에는 선택한 지역 전체 요약을 보여준다
- KPI 3장: 중위 평당가(전년 대비), 최근 12개월 거래 수(전년 대비), 전고점 대비
- 차트: 247개월 중위 평당가 라인. 크로스헤어 + 툴팁
- 표: 최근 12개월 거래 5건 이상 단지를 평당가 순으로. 컬럼은 단지 / 법정동 /
  평당가 / 거래 수

### 모바일 390px

2단이 세로로 접히고 지도가 먼저 온다. 표는 `overflow-x: auto` 컨테이너에 넣어
페이지 본문이 가로로 밀리지 않게 한다. 저장소 규칙상 **390px에서 가로 스크롤이
생기면 안 된다** — 구현 후 headless Chrome으로 `scrollWidth` 를 측정해 확인한다.

### URL 파라미터

`/real-estate/?sgg=11680&metric=chg12&ym=2026-06`

글에서 특정 화면을 바로 가리킬 수 있게 한다. 조작 시 `history.replaceState` 로
주소를 갱신한다.

## 블로그 통합

```
/real-estate/                ← 대시보드 (_pages/real-estate.md)
/real-estate/<글-제목>/       ← 분석 글 (categories: real-estate)
/categories/real-estate/     ← 테마 기본 카테고리 아카이브
```

기존 permalink 규칙 `/:categories/:title/` 이 그대로 적용돼 `_config.yml` 의
permalink 설정을 건드릴 필요가 없다. `_data/navigation.yml` 에 "부동산"을 추가한다.

대시보드 페이지는 `classes: wide` 로 본문 폭을 넓히고 `author_profile: false` 를
쓴다. 대시보드 CSS/JS 는 페이지 전용 파일로 분리해 다른 글에 영향을 주지 않는다.

## 운영

`scripts/daily.sh` 끝에 `build_dashboard.py` 를 붙인다. 매일 04:30 수집 → 집계 →
변경분 커밋·푸시. 출력이 결정론적이라 실제로 값이 바뀐 구의 JSON만 커밋된다.

수집이 일일 한도로 중단된 날에도 집계는 돌린다. 그날까지 받은 데이터로 만든
대시보드가 어제 것보다 낫다.

## 검증

- **집계 함수**: 중위값, 변화율, 회전율을 합성 입력으로 검증. 짝수 개 표본의
  중위값, 표본 0인 달, 해제 건 제외 여부
- **경계 병합**: 병합 결과가 정확히 72개이고 `regions.py` 와 일치하는지. 단순화
  후 빈 path가 없는지
- **결정론**: 같은 입력으로 두 번 빌드해 JSON 바이트가 동일한지
- **크기 예산**: `summary.json` 200KB 이하, 구별 JSON 300KB 이하. 초과 시 실패
- **모바일**: 390px에서 `scrollWidth <= 390`
- **실측 대조**: 강남구 2026-07 중위 평당가가 12,659만원, 2006-01이 2,599만원으로
  나오는지 (이 문서 작성 시 원본에서 직접 계산한 값)

## 이번 범위에서 제외

- 전월세·전세가율 — 원본 데이터를 아직 수집하지 않았다
- 계약해제율 지표 — 2차
- 지도 확대·이동, 단지 상세 팝업, 즐겨찾기
- 읍면동 단위 드릴다운
- 서울·경기 외 지역, 아파트 외 유형
